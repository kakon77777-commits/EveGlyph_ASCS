## 摘要

EveGlyph ASCS v1.0 不是新的 ontology round。它是對既有九個 architecture / hardening stages 的一致性封版與實作交接。

整個架構可以縮成：

$$
\boxed{
\text{Addressable Objects}
+\text{Immutable Revisions}
+\text{Typed Relations}
+\text{Spatial Worlds}
+\text{Native Math}
+\text{Native Glyphs}
+\text{Agent Authority}
+\text{Interchange}
+\text{Operational Evidence}
}
$$

其中真正的 canonical spine 是：

$$
\text{EGIR}
\rightarrow
\text{EGStore}
\rightarrow
\text{EGCR}
$$

而 Markdown、LaTeX、MathML、SVG、PDF、UTF-8X、MCP、CLI、HTTP、AI model、renderer、CAS、index、telemetry 都位於 adapter / runtime / projection / backend 層。

v1.0 的完成條件不是「所有未來功能都已實作」，而是：

$$
\boxed{
\text{A local implementation team can proceed without reconstructing architecture from chat memory.}
}
$$

---

# 1. Canonical World Model

持久物件與 revision 分離：

$$
O_i=(i,k,H_i)
$$

$$
\rho_{i,v}=(i,v,k,c,s,g,b,m).
$$

Persistent identity 回答「是否仍是同一條 lineage」；content address 回答「canonical intrinsic state 是否相同」；version address 回答「是哪個 immutable revision」。

因此：

$$
IdentityEquality
\neq ContentEquality
\neq SemanticEquality
\neq ProjectionEquality.
$$

Clone 可以 content 相同但 identity 不同；edit 可以 identity 相同但 revision/content 不同；move 可以 identity/content/revision 都不變，只改 workspace spatial state。

---

# 2. Address Model

v1.0 保留六類可分離 address：

$$
A=(A^{id},A^{content},A^{sem},A^{space},A^{phys},A^{ver}).
$$

核心規則：

- identity 不依賴 file path；
- content hash 不等於 identity；
- semantic address 可以 zero / one / many resolution；
- spatial address 必須 workspace / snapshot / frame aware；
- physical location 可以遷移或複製；
- immutable version address 不得 rebind。

Resolve 與 dereference 分離：

$$
Resolve(A,\Gamma,Policy)\rightarrow ResolutionResult
$$

$$
Dereference(ResolutionResult)\rightarrow Representation.
$$

而 authorization 又是另一層：

$$
ResolveSuccess
\not\Rightarrow CanRead\lor CanWrite\lor CanExecute.
$$

---

# 3. EGIR — Canonical Object Contract

TW-01 的 `egir/0.1` 仍是 v1.0 的 stable implementation baseline。

Mandatory portable carrier 仍為 UTF-8 JSON；Draft 2020-12 schema 提供 structural validation；`egir-cj/0.1` 提供 hash canonicalization。

v1.0 **沒有**修改：

- key ordering；
- typed exact-number lowering；
- Unicode scalar-sequence preservation；
- content/revision/workspace hash preimages；
- domain separation。

因此 v0.9 → v1.0 沒有 mandatory canonical migration。

---

# 4. EGStore — Replaceable Physical Representation

TW-02 的 storage 原則保持：

$$
\text{EGIR Semantic State}
\neq\text{Physical Representation}.
$$

Chunk identity 定義在 decoded bytes；encoded blob hash 另外保存。重新 chunk、重新壓縮、identity ↔ Brotli/Zstd/UTF-8X、移動 physical location，都不得改 TW-01 object/revision identity。

Storage profile 的評價不能只看 compression ratio；至少必須考慮：

$$
(CR,RA,WA,MR,DR,T_e,T_d,M_{peak}).
$$

---

# 5. EGCR — Runtime Authority Boundary

Live runtime 必須區分：

$$
\boxed{
CanonicalState
\neq SessionOverlay
\neq DerivedCache
\neq ExternalEffects
}
$$

Canonical mutation 統一走：

$$
Command
\rightarrow Resolve
\rightarrow Validate
\rightarrow Authorize
\rightarrow Commit
\rightarrow Persist.
$$

寫入必須 pin `base_workspace_revision`。Stale write 不得 silent last-write-wins。

---

# 6. Persistent Editing / History

v0.3 凍結三類歷史：

$$
CommandIntent
\neq CanonicalCommitDAG
\neq SessionNavigation.
$$

Branch 是同一 workspace identity 內的 mutable head；workspace fork 才建立新 workspace identity。

Committed undo 使用 revert commit，而不是抹除歷史。

Merge 按 domain 分離：

$$
M=M_O\oplus M_P\oplus M_R\oplus M_A\oplus M_L.
$$

Conflict 可以是 first-class canonical state，可以 checkpoint / close / reopen / resolve。

---

# 7. Spatial World

v0.4 將 Infinite Canvas 升為 nested region system。

固定 frame：World、Region、Object-local、View。

Canonical transform 是 column-vector homogeneous affine matrix，保存 `local -> parent`。

View pan/zoom 不是 world mutation。

Reparent 有兩種明確語義：`KeepWorld` 與 `KeepLocal`。

最重要的 boundary：

$$
SpatialContainment
\neq SemanticScope
\neq ExecutionAuthority.
$$

Spatial parser 只產生 candidate relation；promotion 後才可以進 authoritative graph。

---

# 8. Native Math

基線 `ncm/0.1` 保留；v0.5 新增 `ncm/1.0-candidate.1` 作可交接的 richer math profile。

核心原則：

$$
\text{Math Object}
\neq\text{LaTeX String}.
$$

以及：

$$
Canonicalization
\neq MathematicalSimplification.
$$

$$
Computed
\neq Verified
\neq Proved.
$$

Binder、free/bound identity、assumption、constraint、units、exact/approximate numeric state、evidence、rewrite provenance、subexpression address 都保留分離。

v1.0 不把 candidate profile 偷改名 stable。未來正式 promotion 必須另做 component-profile release。

---

# 9. Glyph / Symbol

基線 `glyph/0.1` 保留；v0.6 新增 `glyph/1.0-candidate.1`、family、binding、renderer 與 GSC bridge candidate profiles。

核心分離：

$$
Character
\neq Glyph
\neq SemanticSymbol
\neq Behavior.
$$

以及：

$$
ExactCarry
\neq Geometry
\neq Topology
\neq PartGraph.
$$

Glyph 可以沒有 Unicode code point 仍然是一級 persistent object。

Semantic binding 與 executable behavior 不因圖形外觀自動成立。

$$
ImportGlyph
\not\Rightarrow CanExecute.
$$

---

# 10. Agentic Workspace

v0.7 固定：

$$
AgentPrincipal
\neq ModelBinding
\neq AgentRun
\neq TransportSession.
$$

Agent lifecycle：

$$
Task\rightarrow ContextPack\rightarrow AgentRun\rightarrow Proposal\rightarrow Validate\rightarrow Authorize\rightarrow Review\rightarrow Commit.
$$

`direct` 是 review policy，不是 unlimited authority。

Agent model、CLI、MCP/HTTP transport 都可以換；persistent workspace semantics 不跟著換。

---

# 11. Interchange

v0.8 固定：

$$
LegacyFormat
\neq EveGlyphOntology.
$$

Format adapter 必須回 fidelity report；round-trip 必須聲明 byte-exact、canonical-state、semantic-equivalent、presentation-equivalent 或單向/opaque 類型。

URI / DOI / DID / SWHID 等外部 identifier 只建立 typed external reference：

$$
Resolve_{ext}(r)=Resolved
\not\Rightarrow A^{id}_{local}=r.
$$

真正 federated identity binding 需要 explicit authority + capability + provenance。

---

# 12. Operational Hardening

v0.9 把產品化條件固定為：

$$
Bounded+Observable+Explainable+Recoverable+Migratable+Rollbackable.
$$

安全原則為 default-deny；hard resource budget 超限必須 refuse，而不是 silently degrade 到不同語義。

Unknown external-effect outcome 不得自動重試。

ExplainResolution / ExplainMutation / ExplainExecution 是 handoff contract，而不是 debug UI 偶發訊息。

Release 必須有 rollback target；migration 必須 dry-run / checkpoint / provenance。

---

# 13. v1.0 Version Semantics

v1.0 umbrella version：

```text
ASCS = ascs/1.0
Handoff = ascs-handoff/1.0
```

但 component profile 依各自成熟度保留原 ID。

這是刻意的：

$$
\text{Architecture Stability}
\neq\text{Every Component Is Feature-Complete}.
$$

v1.0 對本地端承諾的是：**你不需要重新決定 object identity、canonicalization、authority、history、space、math/glyph boundary、agent boundary、interchange authority 與 operational gates。**

它沒有承諾 full CAS、full theorem prover、global collaboration、production cloud、mobile、VR 或 universal font system 已完成。

---

# 14. v1.0 Design Freeze

以下是 handoff 後不得 silent change 的核心：

1. persistent identity semantics；
2. object / revision separation；
3. intrinsic / placement separation；
4. content/revision/workspace hash preimages；
5. `egir-cj/0.1` canonicalization；
6. typed six-address separation；
7. mutable alias != immutable citation；
8. candidate != authoritative relation；
9. canonical != session != derived != external effect；
10. stale write requires conflict/rebase/merge handling；
11. layout graph != execution graph；
12. spatial containment != semantic scope；
13. Native Math != notation string；
14. computed != verified != proved；
15. glyph != Unicode character；
16. visual import != execution permission；
17. Agent Principal != model/provider/session；
18. direct mode != bypass authority；
19. legacy format != ontology；
20. external identifier != local persistent identity；
21. physical store != semantic identity；
22. index/cache != canonical truth；
23. operational telemetry failure != canonical operation failure；
24. unknown external effect != safe-to-retry；
25. semantic change under same profile ID is forbidden。

---

# 15. Scope Guard After v1.0

以下內容可在 v1.0 之後開新 implementation / research project，但不能為了它們回頭模糊 v1.0 邊界：

- full theorem prover；
- universal CAS；
- global semantic registry；
- distributed real-time collaboration；
- cloud multi-tenant backend；
- 3D / VR Canvas；
- full font-authoring system；
- mobile native app；
- blockchain identity；
- production-scale federation。

---

# 16. Completion Statement

v1.0 的研究／規格階段到此完成。

未來工作應該主要產生：code、tests、benchmarks、migration evidence、release candidates、UI/product validation。

如果新的工程問題迫使 canonical semantics 改變，必須以 v0.2 compatibility discipline 開新的 profile/version，而不是修改本 package 後假裝 v1.0 從來就是另一個意思。
