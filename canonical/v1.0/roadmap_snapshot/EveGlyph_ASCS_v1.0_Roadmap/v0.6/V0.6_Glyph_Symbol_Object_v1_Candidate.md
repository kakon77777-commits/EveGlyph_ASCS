# 1. 核心命題

EveGlyph v0.6 將以下概念永久拆開：

$$
\boxed{
\text{Character}
\neq
\text{Glyph}
\neq
\text{Semantic Symbol}
\neq
\text{Behavior}
}
$$

並且：

$$
\text{Raster Source}
\neq
\text{Exact Carry}
\neq
\text{Geometry}
\neq
\text{Topology}
\neq
\text{Part Graph}.
$$

Unicode 17.0 的基本原則本來就是 encode characters, not glyphs。OpenType 則負責字型內的 character-to-glyph mapping、outlines、color glyphs、variations 與 layout。v0.6 因此不試圖把 custom glyph 偽裝成 Unicode character，也不把 OpenType glyph ID 升格成 EveGlyph persistent identity。

---

# 2. 非目標

v0.6 不宣稱：

1. 任意圖片都可被完全語義理解；
2. exact pixel reconstruction 等於 semantic understanding；
3. skeleton 一定是唯一或精確 medial axis；
4. 所有 glyph 都應成為 font glyph；
5. 所有 custom glyph 都需要 Unicode code point；
6. image import 自動授予 executable behavior；
7. 同一可見形狀在所有 domain 都具有同一 semantics；
8. renderer output 可作 persistent identity；
9. GSC v1.13 已證明一般視覺抽象理論。

---

# 3. Candidate Profile 邊界

一個 `glyph/1.0-candidate.1` revision 的 intrinsic state 定義為：

$$
G_v=(D,G,T,P,F,R,C).
$$

其中：

- $D$：design space；
- $G$：geometry representation；
- $T$：committed topology；
- $P$：committed structural part graph；
- $F$：optional family/variant binding；
- $R$：render intent / projection hints；
- $C$：compatibility payload descriptors。

**不直接放入 intrinsic 的內容：**

- persistent identity：由 TW-01 object record 提供；
- Canvas placement：由 workspace placement 提供；
- authoritative semantic binding：由 first-class relation / binding commit 提供；
- session permission：由 EGCR capability policy 提供；
- source file path：屬 physical address / provenance；
- AI recognition proposal：屬 candidate layer。

因此：

$$
\boxed{
IntrinsicGlyph
\neq
SemanticBinding
\neq
ExecutionPermission
}
$$

# 4. Design Space

每個 glyph 都有自己的 local design space：

```json
{
  "dimension": "2d",
  "units": "design-unit",
  "origin": "y-up",
  "view_box": ["0", "0", "1000", "1000"]
}
```

v0.6 只凍結 2D glyph profile；未來 3D / volumetric symbol 必須使用新 profile，而不是把 z 軸偷偷塞進現有欄位。

Canonical scalar 使用 decimal string：

```text
0
-12
0.5
125.25
```

不得使用 NaN、Infinity、exponent notation、`-0`、無意義 trailing zero。這延續 TW-01 對 deterministic numerics 的要求。

# 5. Geometry Kernel

v0.6 不為每個視覺形狀建立 object kind，而使用小型 geometry kernel。

## 5.1 Path primitive

核心 path command：

```text
M x y
L x y
Q x1 y1 x y
C x1 y1 x2 y2 x y
Z
```

path 可以指定：

- fill rule；
- structural layer；
- local opacity hint；
- geometry role。

Renderer 可以把 path 投影成 SVG、Canvas2D、OpenType outlines、GPU mesh 或 raster，但投影結果不是 canonical geometry identity。

## 5.2 Component instance

Composite glyph 可以引用另一個 immutable glyph revision：

$$
ComponentInstance=(GlyphRevisionRef,T_{local}).
$$

這使 reusable radicals、operators、ornaments、icons、math glyph components 不必 flatten 成新的 raster。

component reference MUST pin revision；若要跟隨 mutable family head，必須透過另外的 explicit alias resolution policy。

## 5.3 Exact pixel carry

對 GSC / pixel-art domain，v0.6 允許 `palette-runs-v1` exact carry：

$$
Carry=(canvas,palette,RUNs).
$$

它可以 source-blind 重建 target，但：

$$
ExactCarry
\not\Rightarrow
SemanticUnderstanding.
$$

---

# 6. Geometry Authority

`geometry.representations` 可以同時包含：

- `path-graph`；
- `component-graph`；
- `palette-runs-v1`；
- future extension representation。

必須有一個 `canonical_structure` selector，指出哪個 representation 參與此 profile 的 geometry equality。

其他 representations 可以是：

- exact fallback；
- imported projection；
- renderer cache；
- compatibility carry。

不得因同一 glyph 同時有 SVG path 與 pixel carry 就假定兩者 bitwise 等價；必須由 fidelity/evidence record 宣告。

---

# 7. Topology Profile

Committed topology 至少可描述：

$$
T=(Components,Holes,Adjacency,Containment).
$$

`topology` 記錄是結構聲明，不是 renderer 自己猜的 cache。

若 topology 是演算法推導後 promotion 的結果，必須保存：

- derivation event；
- algorithm identifier/version；
- source glyph revision；
- validation/evidence class。

Skeleton / medial representation 不屬 core topology truth。它應存為 derived structural artifact，並標示：

```text
approximate
profile-exact
unknown
```

因此：

$$
SkeletonHint
\neq
TopologyTruth.
$$

---

# 8. Part Graph

Part graph：

$$
P=(V_P,E_P).
$$

每個 part node 可以指向：

- geometry refs；
- child part refs；
- structural tags；
- attachment ports。

Part edge 類型至少包含：

```text
contains
adjacent
attached
aligned
ordered-before
mirrors
```

v0.6 的 `structural_tag` 只能表示結構角色，例如 `stem-like`、`loop-like`、`radial-center`、`component-slot`。語義角色如「微分算子」、「眼睛」、「門」不得因 part recognizer 推測就直接寫成 authoritative symbol semantics。

---

# 9. Port / Attachment Model

為了讓 glyph 能參與 math、diagram、dataflow 與 composite editing，glyph 可以宣告 typed ports：

$$
Port=(id,kind,anchor,direction,cardinality).
$$

例如：

- `math-operand`；
- `connector`；
- `component-anchor`；
- `baseline`；
- `attachment`。

Port 是 structural affordance；它不自動授予 executable semantics。

---

# 10. Glyph Family

Family 使用獨立 profile：

```text
glyph-family/1.0-candidate.1
```

Family object 可以定義：

$$
F=(Base,Axes,Constraints,TopologyPolicy,Defaults).
$$

Axis 分為：

- continuous；
- discrete；
- categorical。

例如：

```text
weight
width
stroke-contrast
corner-radius
state
orientation
```

這與 OpenType variable-font variation space 有互通可能，但 EveGlyph family axis 不等於 OpenType `fvar` axis；adapter 必須顯式映射。

---

# 11. Variant Identity

Variant glyph 是普通 persistent glyph object，透過 family binding：

$$
Variant(g,F,\theta).
$$

可以有：

$$
g_1\neq_{id}g_2
$$

但：

$$
g_1\equiv_{sem}g_2.
$$

若產品需要「同 lineage 的 parameterized revision」也可以建立，但不得把 family parameter equality 和 persistent identity equality 混為一談。

---

# 12. Topology Policy for Families

Family MUST 宣告：

```text
invariant
variant-allowed
```

`invariant` 表示所有合法 parameter instance 的 committed topology 類型必須保持相容。

`variant-allowed` 則表示 axis 可能跨 topology boundary；renderer/editor 不得假定 point correspondence 永遠存在。

---

# 13. Renderer Profile

Renderer contract：

$$
Render_{r,v}(GlyphRevision,Context)
\rightarrow
Projection.
$$

Renderer profile 至少聲明：

- renderer ID/version；
- supported geometry representation；
- target surface；
- fidelity class；
- fallback policy；
- deterministic / nondeterministic status。

Fidelity classes：

```text
exact
structural
visual
lossy
unknown
```

Renderer output MUST NOT 具有 identity authority。

---

# 14. Unicode Boundary

Unicode 17.0 明確區分 characters 與 glyphs，且允許多 character ↔ glyph 的複雜 mapping。

因此 v0.6 使用 adapter relation：

```text
eg:denotesUnicodeSequence
```

target 是一個 code point sequence，而不是把 code point 寫成 glyph identity。

合法情況包括：

$$
OneCharacter\rightarrow ManyGlyphs,
$$

$$
ManyCharacters\rightarrow OneGlyph,
$$

$$
OneGlyph\rightarrow NoUnicodeCharacter.
$$

Custom glyph 完全可以在沒有 Unicode assignment 的情況下持續存在。

---

# 15. OpenType / Font Adapter Boundary

OpenType 1.9.1 提供 character-to-glyph mapping、TrueType/CFF/CFF2 outlines、SVG color glyph、COLR/CPAL color composition、font variations 與 MATH layout 等成熟機制。

v0.6 將 OpenType 視為 font ecosystem adapter：

$$
Map_{OT}:GlyphRevision\leftrightarrow(FontDigest,GlyphID,VariationLocation).
$$

其中 `GlyphID` 只在特定 font binary 中有意義，不是 EveGlyph persistent ID。

OpenType SVG table、COLR v1 paint graph、variable glyph outlines 都可作 export/import target，但 adapter MUST 報告 fidelity。

---

# 16. Semantic Binding Authority

語義 binding 使用 first-class relation：

```text
eg:represents
```

例如：

$$
Glyph(g)\xrightarrow{eg:represents}MathSymbol(derivative).
$$

AI / recognizer 推測只能先建立 candidate：

$$
Recognize(g)\rightarrow\widehat{Binding}.
$$

只有：

$$
Promote(\widehat{Binding},authority)\rightarrow Binding
$$

才成為 committed semantics。

---

# 17. 與 v0.5 Native Math 的接口

v0.5 使用 versioned semantic symbol registry。v0.6 glyph 可以顯式綁定：

```text
registry: eg-math-core
symbol: derivative
version: 1
```

但 math expression graph 中 canonical operator identity 仍是 semantic symbol ref，而不是 glyph revision。

因此：

$$
\boxed{
MathOperatorIdentity
\neq
GlyphIdentity
}
$$

同一 derivative operator 可以用 Leibniz notation、自訂 glyph、文字按鈕或 accessibility projection 表示。

---

# 18. Behavior Binding

可執行 behavior 使用獨立 predicate，例如：

```text
eg:invokesOperator
```

Binding record 可以聲明 required capability：

```text
runtime.execute
```

但 capability grant 永遠來自 runtime session/policy，不來自 glyph intrinsic。

所以：

$$
ImportGlyph
\not\Rightarrow
CanExecute.
$$

即使 glyph 已經 `eg:represents derivative`，也不代表 session automatically can invoke derivative backend。

---

# 19. Source → Glyph Compilation Provenance

完整 pipeline：

$$
S_0
\xrightarrow{Normalize}
S_1
\xrightarrow{ExactCarry}
S_2
\xrightarrow{StructuralLift}
S_3
\xrightarrow{PartParse}
S_4
\xrightarrow{SemanticProposal}
\widehat B
\xrightarrow{Promote}
B.
$$

每一階段 MUST 分別記錄：

- input revision/artifact hash；
- tool/algorithm version；
- parameters；
- output revision/artifact hash；
- fidelity/evidence；
- authority class。

不能只保存一個「AI generated」布林值。

---

# 20. GSC AssetSymbol v0.7 Compatibility

現有 GSC v1.13 的 canonical strict representation 是 AssetSymbol v0.7，核心欄位包含：

```text
canvas
palette
RUN tokens
regions
adjacency
topology
partGrammar
normalization?
stats
```

v0.6 bridge mapping：

| GSC v0.7 | Glyph v1 Candidate |
|---|---|
| `canvas` | design space / pixel-grid descriptor |
| `palette + tokens` | exact carry `palette-runs-v1` |
| `regions` | topology component candidates / region refs |
| `adjacency` | topology adjacency |
| `topology` | committed or candidate topology,依 bridge authority |
| `partGrammar` | structural part graph candidate/import |
| `normalization` | derivation provenance |
| `stats` | diagnostic metadata，不作 semantic authority |

Bridge MUST preserve GSC 的 source-blind evidence boundary：

$$
GSCExactReconstruction
\not\Rightarrow
GlyphSemanticBinding.
$$

# 21. GSC Compatibility Classes

v0.6 定義：

```text
carry-lossless
structure-preserving
structure-partial
visual-only
unsupported
```

對 AssetSymbol v0.7 的 `palette + RUN`，若 bridge 不修改 bytes/indices semantics，可宣告 `carry-lossless`。

對 topology / partGrammar，如果 v0.6 schema 無法保留全部欄位，必須降為 `structure-partial`，不可假裝 lossless。

# 22. Equality Family

v0.6 正式區分：

## 22.1 Exact carry equality

$$
g_1\equiv_{carry}g_2.
$$

## 22.2 Geometry equality

$$
g_1\equiv_{geo,\Gamma}g_2.
$$

需指定 normalization/frame profile。

## 22.3 Topological equality

$$
g_1\equiv_{topo}g_2.
$$

可依 graph isomorphism / declared topology signature。

## 22.4 Part-structural equality

$$
g_1\equiv_{part}g_2.
$$

## 22.5 Family-coordinate equality

$$
(g_1,F,\theta_1)\equiv_{family}(g_2,F,\theta_2)
$$

只在同 family/profile 下定義。

## 22.6 Semantic equality

由 authoritative bindings / theory 決定：

$$
g_1\equiv_{sem}g_2.
$$

任何一種 equality 都不得偷換成 persistent identity equality。

# 23. Geometry Canonicalization

v0.6 geometry canonicalization 只做 representation normalization，不做視覺「美化」。

MUST：

- canonical scalar grammar；
- path / part / topology IDs lexical ordering；
- explicit command order preservation；
- component refs pin immutable revision；
- reject duplicate IDs；
- reject dangling refs；
- reject invalid path command sequence；
- reject cyclic component expansion unless future profile explicitly允許 bounded recursion。

MUST NOT：

- 自動重排 path 以追求更短 bytes；
- 自動把相似曲線合併；
- 自動修改 winding；
- 自動變更 topology；
- 自動把 AI recognition 結果寫入 semantics。

---

# 24. Component Expansion Safety

Composite glyph expansion：

$$
Expand(g,depth,budget).
$$

Runtime MUST 有：

- max component depth；
- max expanded primitives；
- cycle detection；
- decoded byte/resource limits。

這同時避免 recursive glyph bombs 與 malformed imported font/component graph。

---

# 25. Renderer / Import Security

Imported SVG/font/glyph assets MUST 被當作 data，而不是一般 browser document 或 script container。

特別是：

- SVG scripts / event handlers 不得成為 glyph behavior；
- external resource loading 預設 disabled；
- embedded font program / hinting engine 必須走 sandboxed font parser policy；
- raster metadata 不具有 execution authority；
- font glyph ID 不具有 global identity authority。

OpenType 自身也對 font-contained SVG 的 expressiveness 作限制；v0.6 更進一步要求 EveGlyph import pipeline 不直接繼承任意 SVG DOM behavior。

---

# 26. Accessibility Projection

一個 custom glyph 若沒有 Unicode mapping，仍 MUST 能透過 semantic binding、description、structural tree 或 fallback label 產生非視覺 projection。

因此 accessibility 不應建立在：

```text
if no Unicode code point -> impossible
```

而應建立在：

$$
Glyph\rightarrow Semantic/StructuralProjection.
$$

---

# 27. Semantic Zoom

Glyph 可以依 zoom/context 使用不同 renderer profile：

$$
Render(g,z_1)\neq Render(g,z_2),
$$

但：

$$
A^{id}_{z_1}=A^{id}_{z_2}.
$$

低 zoom 可顯示 simplified silhouette，高 zoom 展開 part boundaries、ports、control points。這只是 projection variation。

---

# 28. Editing Operations

v0.6 定義最小 glyph operations：

```text
EditGeometry
EditTopology
EditPartGraph
AddComponent
RemoveComponent
SetFamilyBinding
SetRenderHint
ImportCarry
CreateBindingCandidate
PromoteBinding
RevokeBinding
```

前七項若修改 intrinsic，建立新 glyph revision。

`CreateBindingCandidate` 不修改 glyph intrinsic。

`PromoteBinding` / `RevokeBinding` 修改 relation/binding history，而不是偷偷重寫 geometry hash。

---

# 29. Merge Semantics with v0.3

Glyph merge 必須拆 domain：

$$
M_G\oplus M_T\oplus M_P\oplus M_F\oplus M_R.
$$

典型情況：

- 左 branch 改 geometry、右 branch 只改 Canvas placement：可獨立 merge；
- 左右 branch 修改不同 part：若 refs 不交疊，可結構 merge；
- 左右 branch 同時修改同一 path command：產生 geometry conflict；
- 一邊刪除 component、一邊修改其 transform：產生 delete-vs-edit conflict；
- semantic binding conflict 由 relation layer 處理，不塞進 geometry merge。

# 32. Conformance Vectors

v0.6 至少要求以下類別：

- custom glyph without Unicode；
- same semantic symbol / different glyphs；
- same glyph / ambiguous semantic candidates；
- renderer change preserves identity；
- Canvas move preserves intrinsic revision；
- geometry edit creates revision；
- topology edit creates revision；
- family variant binding；
- component revision pinning；
- component cycle rejection；
- malformed path rejection；
- candidate binding non-authority；
- promotion creates authoritative relation；
- imported behavior remains disabled；
- execution requires `runtime.execute`；
- OpenType GlyphID non-global identity；
- Unicode mapping optional；
- ligature-style many-character mapping；
- GSC carry-lossless bridge；
- GSC semantic non-claim；
- source deletion after exact carry does not destroy glyph；
- skeleton hint non-topology authority；
- part role candidate non-semantic authority；
- cross-profile fidelity downgrade；
- geometry/topology/semantic equality separation；
- semantic zoom identity stability；
- geometry merge conflict；
- relation binding conflict separate from geometry；
- legacy `glyph/0.1` coexistence；
- explicit enrichment migration。

本輪封裝固定為 **30 組 vectors**。

# 33. Candidate → v1.0 Promotion Conditions

`glyph/1.0-candidate.1` 在 v1.0 前至少必須滿足：

1. 至少兩個獨立 renderer 可消費同一 canonical glyph example；

5. imported glyph 不會自動執行；
6. family/variant 可以跨 save/load 保留 parameter semantics；
7. component cycle / resource bombs 被拒絕；
8. equality classes 有 machine-readable tests；
9. adapter fidelity 不 silent 升格；
10. legacy `glyph/0.1` 不被重新解釋。

# 35. Design Freeze

v0.6 完成後，後續 v0.7–v1.0 不得 silent 改變以下決策：

1. Character、Glyph、Semantic Symbol、Behavior 分離；
2. glyph persistent identity 不依賴 Unicode；
3. GlyphID/font path 不作 global identity；
4. intrinsic geometry 與 Canvas placement 分離；
5. semantic binding 不直接塞入 glyph intrinsic authority；
6. behavior binding 與 semantic representation 分離；
7. execution capability 不來自 glyph；
8. small geometry kernel + extensible representations；
9. exact carry 與 structural geometry 分離；
10. exact reconstruction 不等於 semantic understanding；
11. topology 與 skeleton hint 分離；
12. part graph structural role 不自動升格 semantics；
13. component refs pin immutable revision；
14. family/variant 是獨立 identity/parameter問題；
15. family topology policy 必須 explicit；
16. renderer 是 projection，無 identity authority；
17. Unicode/OpenType/SVG/COLR 都是 adapter ecosystem；
18. semantic binding candidate → promotion；
19. GSC AssetSymbol v0.7 有 explicit bridge profile；
20. GSC source-blind carry evidence不得誇大為 semantic evidence；
21. equality 必須 typed；
22. imported SVG/font behavior 預設 non-executable；
23. accessibility 不依賴 Unicode assignment；
24. legacy `glyph/0.1` coexistence；
25. enrichment migration 建立新 revision。

# 36. Handoff Boundary

本地端未來可自由替換：

- path tessellator；
- renderer；
- font parser；
- SVG renderer；
- topology algorithm；
- skeletonizer；
- part recognizer；
- GSC compiler implementation；
- semantic recognizer；
- AI model。

但不得 silent 改變：

- profile semantic meaning；
- persistent identity semantics；
- geometry canonical number grammar；
- component revision pinning；
- semantic/behavior authority boundary；
- equality class meaning；
- migration discipline。

# 37. 結論

v0.5 完成：

$$
\boxed{\text{Mathematics as Native Object}}
$$

v0.6 完成下一塊：

$$
\boxed{\text{Visible Symbol as Native Object}}
$$

真正的 custom symbol 不再是：

```text
一張 PNG
一個 Unicode code point
一個 LaTeX macro
一個 font glyph ID
```

而是：

$$
\boxed{
\text{Addressable Geometry}
+
\text{Topology}
+
\text{Part Structure}
+
\text{Family/Variant}
+
\text{Explicit Semantic Binding}
+
\text{Controlled Behavior Binding}
}
$$

這使 GSC 與 EveGlyph 的關係正式收斂：GSC 提供 source → symbolic/structural compilation pipeline；EveGlyph 提供 persistent object、version、relation、semantic symbol、Canvas 與 runtime authority。

下一輪 v0.7 將不再擴張 glyph，而進入：

$$
\boxed{\text{Agentic Workspace Contract}}
$$

把 AI proposal、agent identity、base revision、capabilities、context pack、external effects、MCP/CLI/HTTP/file-agent transport 與 deterministic validator boundary 正式凍結。
