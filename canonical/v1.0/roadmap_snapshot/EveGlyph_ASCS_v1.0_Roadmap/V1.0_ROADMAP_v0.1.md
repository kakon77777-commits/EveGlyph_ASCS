# EveGlyph ASCS v0.2 → v1.0 Canonical Handoff Roadmap

**作者：** Neo.K / EveMissLab  
**版本：** Roadmap v0.1  
**日期：** 2026-08-24  
**前置基線：** ASCS v0.1 Architecture Complete + EveGlyph Computational Canvas MVP-01 v0.1

---

## 1. Roadmap 定位

v0.1 已完成：

$$
6\text{ Papers}+3\text{ Technical Whitepapers}+1\text{ Executable MVP}.
$$

接下來的目的不是在本對話中把 EveGlyph 做成 production product，而是把現有架構逐輪收斂成 **v1.0 canonical handoff package**。v1.0 完成後，再交給本地端進行長期工程化、效能最佳化、UI/UX 重構、平台整合與正式產品升級。

後續每一輪遵守：

$$
\boxed{
\text{One Round}
=\text{One Version}
=\text{One Freeze Boundary}
}
$$

每輪都必須：

1. 有明確新增問題；
2. 不重新打開已凍結且無必要修改的上層 ontology；
3. 提供 design-freeze decisions；
4. 提供 conformance / handoff checklist；
5. 能被下一版直接引用，而不依賴聊天記憶。

---

# 2. Version Ladder

## v0.2 — Contract Hardening & Compatibility Freeze

**核心問題：** 不同版本的 EGIR / EGStore / EGCR / MVP 未來如何共同存在，而不 silent reinterpretation？

凍結：

- layer version tuple；
- compatibility classes；
- migration contract；
- feature/capability negotiation；
- extension namespaces；
- deprecation rules；
- golden vectors governance；
- release artifact obligations；
- `No Silent Reinterpretation` 原則。

**完成標誌：** v0.1 之後任何 schema/runtime/storage 升版都有明確 compatibility/migration path。

---

## v0.3 — Persistent Editing, History & Merge Semantics

**核心問題：** local-first 長期編輯如何在多 branch、多 session、多 agent 下保持 object lineage 與可回溯性？

凍結：

- command log / workspace commit log；
- branch / fork / merge classes；
- object-content / placement merge separation；
- conflict object；
- undo/redo 與 history rewrite boundary；
- checkpoint / autosave semantics；
- session recovery；
- history compaction 不變量。

**完成標誌：** runtime history 不再只是 demo transaction，而成為可交接的 persistent editing model。

---

## v0.4 — Spatial Region, Nested Canvas & Local Grammar Freeze

**核心問題：** Infinite Canvas 如何從單層拖曳 demo 收斂成可巢狀、局部形式化的語法空間？

凍結：

- nested regions；
- local frames；
- region policy inheritance；
- semantic zoom；
- explicit / derived spatial relations；
- region grammar profiles；
- spatial snapshot / address stability；
- layout/execution graph compiler boundary。

**完成標誌：** Canvas 具有正式 spatial-language contract，而不只是 viewport。

---

## v0.5 — Native Math Object v1 Candidate

**核心問題：** Paper 03 的 NCM 如何從最小 $x^2\rightarrow2x$ vertical slice 收斂成可交接的 math object profile？

凍結：

- expression graph core nodes；
- binders / alpha-equivalence；
- assumptions / constraints；
- exact / approximate numerics；
- units / dimensions；
- undefined / conditional / unresolved；
- proof/computation evidence classes；
- LaTeX / MathML / OpenMath adapter fidelity classes。

**完成標誌：** 本地端未來能在不重設 math ontology 的情況下擴充 CAS/prover。

---

## v0.6 — Glyph / Symbol Object v1 Candidate

**核心問題：** Paper 04 的 custom glyph 如何正式連接 GSC、EveGlyph Symbol IR 與 semantic operator？

凍結：

- geometry/topology/part graph profile；
- source → normalized → carry → structure → semantic glyph provenance；
- glyph family / variants；
- renderer profiles；
- Unicode/font adapter boundary；
- semantic binding authority；
- behavior permission；
- GSC compatibility profile。

**完成標誌：** 自訂符號不依賴 Unicode code point，也不依賴 raster source 才能持續存在。

---

## v0.7 — Agentic Workspace Contract

**核心問題：** AI 如何操作 EveGlyph world，而不把模型輸出變成 canonical authority？

凍結：

- proposal / candidate / commit lifecycle；
- agent identity / provenance；
- base-revision pinning；
- tool capabilities；
- review / patch / direct policy；
- context pack boundary；
- external effects；
- MCP/CLI/HTTP/file-agent adapter contract；
- deterministic validator boundary。

**完成標誌：** 本地端可以替換模型、agent CLI、MCP transport 而不重寫 canonical workspace semantics。

---

## v0.8 — Interchange & Legacy Adapter Freeze

**核心問題：** EveGlyph 如何進入既有文件與工具生態，而不重新讓 legacy format 變成 ontology？

凍結：

- Markdown adapter；
- LaTeX adapter；
- MathML / OpenMath adapter；
- SVG / raster adapter；
- PDF/static projection boundary；
- JSON/CBOR/UTF-8X storage profiles；
- import fidelity diagnostics；
- round-trip classes；
- external URI/DOI/DID/SWHID reference adapters。

**完成標誌：** legacy ecosystem 可以輸入/輸出，但 canonical state 仍是 EGIR。

---

## v0.9 — Productization & Operational Hardening Freeze

**核心問題：** 哪些工程條件必須在 v1.0 handoff 前固定，才能避免本地端拿到一個只有理論的包？

凍結：

- security boundary；
- resource limits；
- crash recovery；
- observability / diagnostics；
- ExplainResolution / ExplainMutation / ExplainExecution；
- benchmark matrix；
- performance budget classes；
- packaging layout；
- migration tooling requirements；
- release / rollback checklist；
- compatibility test matrix。

**完成標誌：** v1.0 可以直接轉交 implementation team / local AI，而不必重建工程邊界。

---

## v1.0 — Canonical Architecture & Local Handoff Freeze

v1.0 **不再增加核心 subsystem**。它只做收斂：

- 對 v0.2–v0.9 所有 freeze 做一致性審核；
- 移除重複/矛盾 terminology；
- 凍結 v1.0 namespace、version matrix、compatibility baseline；
- 建立 Canonical Architecture Map；
- 建立 Local Implementation Handoff；
- 建立 MVP → Product migration map；
- 建立 prioritized implementation backlog；
- 建立 test/benchmark/release gates；
- 建立「哪些可以改、哪些不能 silent 改」清單；
- 建立完整 SHA-256 release manifest。

v1.0 的完成條件：

$$
\boxed{
\text{A local implementation agent can start from the package, not from chat memory.}
}
$$

# 3. Three-Stage View

可以將整個路線壓縮成：

$$
\text{v0.2--v0.4}
=\text{Contract + Editing + Space}
$$

$$
\text{v0.5--v0.7}
=\text{Math + Glyph + Agent}
$$

$$
\text{v0.8--v0.9}
=\text{Interop + Product Hardening}
$$

最後：

$$
\text{v1.0}=\text{Canonical Handoff Freeze}.
$$

---

# 4. Scope Guard

在 v1.0 前，以下內容預設 **不展開成新的獨立系列**：

- 3D / VR Canvas；
- distributed global collaboration；
- blockchain identity；
- full theorem prover；
- universal CAS；
- full font system；
- production cloud backend；
- mobile application；
- real-time multiplayer；
- global semantic registry。

如果這些未來需要，應在 v1.0 之後作為子專案展開，而不是污染本輪 canonical handoff。

---

# 5. Round Rule

後續聊天節奏固定為：

> 使用者：「好的。我們繼續完成。」  
> 當輪只完成下一個版本，不偷跑兩版，不重新問已經凍結的決策。

因此下一輪順序固定為：

$$
v0.2\rightarrow v0.3\rightarrow v0.4\rightarrow v0.5\rightarrow v0.6\rightarrow v0.7\rightarrow v0.8\rightarrow v0.9\rightarrow v1.0.
$$
