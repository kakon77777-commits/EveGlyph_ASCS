# 摘要

Paper 02 已定義 Spatial Syntax 與 Infinite Canvas 的基礎權威邊界：transient placement、derived candidate、explicit committed relation 必須分離，layout graph 與 execution graph 也不得預設相同。TW-03 進一步將 viewport、selection、drag preview、spatial index 與 render cache 放回 Session / Derived layer，只有 transaction commit 才能修改 canonical workspace。

然而，v0.1 MVP 的 Canvas 仍主要是單層 world placement。真正可長期交接的 EveGlyph 必須處理更複雜的情況：一個 region 可以包含另一個 region；每個 region 可以有自己的 local coordinate frame；移動父 region 時子物件應保持 local placement 卻改變 world placement；reparent 時必須區分「保持世界位置」與「保持局部位置」；region 可以具有不同 grammar、namespace、execution policy、snap/tolerance profile；semantic zoom 可以改變呈現細節但不能偷偷改變 semantic object；跨 region 的 proximity 不應自動建立 relation；跨 region 的 execution edge 則必須通過明確的 export/import 或 port boundary。

v0.4 提出 **Spatial Region and Local Grammar Model, SRLGM**。SRLGM 將 Canvas 空間分成四個 frame 層：World Frame、Region-local Frame、Object-local Frame 與 View Frame；採明確的 column-vector homogeneous affine transform convention，讓 nested transforms 在不同實作中具有唯一組合順序。Region parentage 採單一 canonical parent 的有向無環森林；跨 region graph relations 使用一般 relation object 表達，不允許用多 parent 空間 containment 偷渡 graph semantics。

每個 region 可以宣告 local policy 與 grammar profile，但 policy inheritance 必須使用固定的 resolver classes：`inherit`、`override-nearest`、`merge-set`、`intersect-capability`、`deny-dominates`。這避免不同 runtime 對「父層 policy 如何傳入子層」各自猜測。Region geometry containment 只能形成 candidate membership；semantic scope、namespace membership 與 execution domain 必須由 explicit committed policy / relation 決定。

v0.4 亦定義 reparent semantics、semantic zoom、cross-region relation boundary、execution graph composition、spatial addressing stability、region deletion、spatial merge/conflict classes，以及 `org.evemisslab.spatial-region/0.1`、`org.evemisslab.spatial-grammar/0.1`、`org.evemisslab.spatial-policy/0.1`、`org.evemisslab.semantic-zoom/0.1` extension profiles。

本輪附帶 machine-readable schema、example profile 與 18 組 conformance vectors，涵蓋 nested transform、KeepWorld/KeepLocal reparent、cycle rejection、policy inheritance、semantic zoom non-authority、cross-region relation、execution port boundary、placement merge/conflict 與 session collapse 等行為。

# 3. Region 是 First-Class Object，但 Parentage 屬 Spatial State

Region 本身是 `kind="region"` 的 persistent object：

$$
r=(i_r,v_r,B_r,F_r,Policy_r,Grammar_r,Projection_r,Metadata_r).
$$

其中：

- $i_r$：persistent identity；
- $B_r$：intrinsic boundary / shape description；
- $F_r$：local frame definition；
- $Policy_r$：local policy declaration；
- $Grammar_r$：local grammar binding；
- $Projection_r$：semantic zoom / projection hints。

但 region 在另一個 region 中的 **placement / parent membership** 預設屬 workspace spatial state，而不是 intrinsic content。

因此純粹把 region A 從 world reparent 到 region B，可以滿足：

$$
A^{content}(A)_{before}=A^{content}(A)_{after}
$$

而 workspace revision 改變。

# 4. Canonical Parent Hierarchy

定義 region parent relation：

$$
Parent:R\rightharpoonup R.
$$

每個 region 最多只有一個 canonical spatial parent。

整體 parent graph 必須是有向無環森林：

$$
G_R=(R,E_{parent}),
$$

且：

$$
Cycle(G_R)=false.
$$

原因不是限制 semantic graph，而是保持 coordinate composition、policy inheritance 與 containment path 可唯一解析。

跨 region 的多對多關係，例如：

- dependsOn；
- references；
- mirrors；
- synchronizesWith；
- semantic similarity；

全部使用 Paper 01 / TW-01 first-class relation object 表達，不得透過「多 parent spatial containment」偷渡。

# 5. 四層 Coordinate Frames

v0.4 正式凍結四類 frame：

## 5.1 World Frame

$$
F_W.
$$

Workspace 的最高層 logical spatial frame。

## 5.2 Region-local Frame

每個 region $r$ 有：

$$
F_r.
$$

## 5.3 Object-local Frame

每個具有 intrinsic geometry 的 object 可有：

$$
F_o^{local}.
$$

## 5.4 View Frame

UI / screen / print / projection 使用：

$$
F_V.
$$

重要邊界：

$$
F_V\text{ mutation}
\not\Rightarrow
W\text{ mutation}.
$$

Pan、zoom、screen DPI、window resize 不得生成 canonical workspace revision。

# 6. Transform Convention

這一節是 v0.4 的 interoperability freeze。

## 6.1 Homogeneous column vectors

點表示為：

$$
\mathbf p=
\begin{bmatrix}
x\\y\\1
\end{bmatrix}.
$$

2D affine transform 使用：

$$
T=
\begin{bmatrix}
a&c&e\\
b&d&f\\
0&0&1
\end{bmatrix}.
$$

轉換：

$$
\mathbf p_{parent}=T_{local\rightarrow parent}\mathbf p_{local}.
$$

## 6.2 Composition order

若 object $o$ 位於 region $r_2$，而 $r_2$ 位於 $r_1$：

$$
T_{o\rightarrow W}
=
T_{r_1\rightarrow W}
T_{r_2\rightarrow r_1}
T_{o\rightarrow r_2}.
$$

也就是最右側 transform 先作用於 local point。

任何 serializer / renderer adapter 若使用不同 matrix convention，必須在 adapter boundary 轉換，不能改 canonical meaning。

## 6.3 Non-invertible transform

若：

$$
\det(T)=0,
$$

則需要 inverse 的操作，例如 KeepWorld reparent，必須回 typed failure：

```text
NonInvertibleTransform
```

不能用近似 inverse 靜默繼續。

---

# 7. Nested World Transform

對 ancestor chain：

$$
r_0\rightarrow r_1\rightarrow\cdots\rightarrow r_n\rightarrow o,
$$

world transform：

$$
T_{o\rightarrow W}
=
T_{r_0\rightarrow W}
\prod_{k=1}^{n}T_{r_k\rightarrow r_{k-1}}
T_{o\rightarrow r_n}.
$$

實作必須使用固定 ancestor order，不得依 DOM traversal accident 或 hash-map iteration order。

---

# 8. Reparent Semantics

Reparent 必須明確指定 mode。

## 8.1 KeepWorld

使用者把 object 拖入另一 region，但視覺上保持世界位置。

舊 world transform：

$$
T_W^{old}.
$$

新 parent world transform：

$$
T_P^{new}.
$$

新 local transform：

$$
T_{local}^{new}
=
(T_P^{new})^{-1}T_W^{old}.
$$

因此：

$$
T_W^{new}=T_W^{old}.
$$

`KeepWorld` SHOULD 是一般 drag-and-drop reparent 的預設使用者行為。

## 8.2 KeepLocal

保持 local transform：

$$
T_{local}^{new}=T_{local}^{old}.
$$

因此 world transform 可能改變。

這適用於 template insertion、component relocation、local coordinate reuse。

## 8.3 Reparent is not intrinsic edit

若 object intrinsic state 未改：

$$
A^{content}_{before}=A^{content}_{after}.
$$

Reparent 產生新的 workspace revision / spatial state，而不是新的 object intrinsic revision。

---

# 9. Region Boundary 與 Membership

幾何包含：

$$
Inside_{geo}(o,r)
$$

只能生成 candidate：

$$
\widehat{MemberOf}(o,r).
$$

Canonical parent / membership 必須由：

- explicit reparent command；
- explicit committed membership relation；
- 已宣告的 auto-adopt policy + deterministic commit rule；

建立。

因此：

$$
Inside_{geo}(o,r)
\not\Rightarrow
Parent(o)=r.
$$

---

# 10. Region Policy Model

每個 region 可宣告 local policy map：

$$
P_r=\{k\mapsto(v,mode)\}.
$$

v0.4 凍結五種 inheritance mode。

## 10.1 `inherit`

若 local 未設定，沿 ancestor 取最近有效值。

## 10.2 `override-nearest`

最近 region 的明確值覆蓋 ancestor。

## 10.3 `merge-set`

ancestor 與 child set 做 deterministic union。

## 10.4 `intersect-capability`

權限 / capability 採交集：

$$
Cap_{eff}=\bigcap Cap_r.
$$

child 不能自己擴張 parent 禁止的 capability。

## 10.5 `deny-dominates`

若 ancestor 任一層為 deny：

$$
Deny\Rightarrow Deny_{effective}.
$$

這適用於 execution、network、external effect 等高風險 policy。

---

# 11. Effective Policy Resolver

對 object $o$ 的 region chain：

$$
Path(o)=(r_0,r_1,\ldots,r_n),
$$

定義：

$$
P_{eff}(o)
=
ResolvePolicy(Path(o),P_{workspace}).
$$

Resolver MUST deterministic，並 SHOULD 提供：

$$
ExplainPolicy(o,key)
\rightarrow
(value,sourceChain,resolutionRule).
$$

避免使用者或 AI 只看到「執行被拒絕」卻不知道是哪一層 region policy 造成。

---

# 12. Semantic Scope 不等於 Spatial Parent

Region 可以提供 namespace / lexical / mathematical / execution scope，但 scope establishment 必須 explicit。

例如：

$$
Parent(o)=r
$$

不推出：

$$
ScopedBy(o,r).
$$

若 region profile 宣告：

```text
scope_mode = explicit-membership
```

則只有 committed `ScopedBy` relation 才建立語義 scope。

若未來某 domain 使用：

```text
scope_mode = parent-bound
```

也必須是明確 versioned grammar/policy，不得由 renderer 猜測。

---

# 13. Local Grammar Profile

Region grammar：

$$
G_r=(id,version,domain,parser,authorityPolicy,ports,extensions).
$$

例：

- `freeform/0.1`；
- `math-layout/0.1`；
- `dataflow/0.1`；
- `glyph-design/0.1`；
- `proof-board/0.1`。

同一 Canvas 可以：

$$
G_{r_1}\neq G_{r_2}.
$$

Local grammar 不需要全 workspace 唯一。

---

# 14. Grammar Inheritance

v0.4 預設 grammar resolution：

1. child 若 explicit grammar，使用 child grammar；
2. child 若 `inherit`，取最近 ancestor grammar；
3. 沒有 grammar 時使用 workspace default；
4. 沒有 default 時視為 `freeform/0.1`。

不得同時自動合併兩個 unrelated grammar 成新的 authoritative grammar。

若要 composition，必須引用明確的 composite grammar profile：

$$
G_c=Compose(G_a,G_b,Rules_c).
$$

---

# 15. Region-local Spatial Parse

對 region snapshot：

$$
S_r=(Objects_r,Placements_r,Geometry_r,Grammar_r,Policy_r).
$$

parse：

$$
Parse_{G_r}(S_r)
\rightarrow
(Candidates_r,Diagnostics_r).
$$

每個 candidate MUST 保存：

- region ID；
- grammar ID/version；
- spatial snapshot / workspace revision；
- source objects；
- rule ID；
- confidence / ambiguity；
- derivation provenance。

Candidate 不具 explicit authority。

---

# 16. Derived Relation 不預設跨 Region

對兩個不同 region：

$$
Parent(a)=r_a,
$$

$$
Parent(b)=r_b,
$$

且：

$$
r_a\neq r_b,
$$

proximity/alignment 等 geometry-derived rule 預設不能跨 boundary 推導：

$$
Near(a,b)
\not\Rightarrow
\widehat Relation(a,b).
$$

除非存在：

- explicit cross-region grammar；
- bridge region；
- declared world-level parser；
- explicit connector / port。

這避免兩個相鄰但語義獨立的區域因畫面靠近而互相污染。

---

# 17. Cross-Region Explicit Relations

Explicit relation 可以跨 region：

$$
e=(a,predicate,b).
$$

其存在不依賴兩物件的 geometric proximity。

移動 region 後，只要 source/target identities 未改：

$$
e_{before}\equiv_{id}e_{after}.
$$

因此 connector routing 是 projection；endpoint / predicate 才是 semantic authority。

---

# 18. Cross-Region Execution Boundary

Local executable region 可以編譯：

$$
Compile(G_r,E_r^{explicit})\rightarrow X_r.
$$

跨 region execution edge 預設需要 typed export/import port：

$$
PortOut(a,r_a)
\rightarrow
PortIn(b,r_b).
$$

沒有 port / policy contract 時：

$$
SpatialAdjacency
\not\Rightarrow
ExecutionDependency.
$$

跨 region execution SHOULD 經：

$$
Export
\rightarrow
BoundaryValidation
\rightarrow
Import
\rightarrow
ComposeExecutionGraph.
$$

---

# 19. Execution Graph Composition

Workspace execution graph：

$$
X_W=Compose(\{X_r\},E_{cross}^{explicit},Policy).
$$

如果 region 只做 layout / freeform：

$$
X_r=\varnothing.
$$

Semantic zoom、viewport、region collapse/expand 不得改：

$$
Hash(X_W).
$$

除非使用者明確 commit 了影響 canonical relations / policies 的 mutation。

---

# 20. Semantic Zoom

Semantic zoom 是 projection policy：

$$
Z(o,z,context)\rightarrow Projection.
$$

可能依 zoom band 顯示：

- title only；
- compact formula；
- full object；
- expanded proof；
- glyph simplified rendering；
- aggregate region summary。

但：

$$
Projection_{z_1}(o)\neq Projection_{z_2}(o)
$$

不推出：

$$
A^{content}_{z_1}\neq A^{content}_{z_2}.
$$

也不推出 execution graph mutation。

AI-generated summary 若未 explicit commit，只能是 derived cache / projection artifact。

---

# 21. Region Collapse / Expand

`collapsed` / `expanded` 預設是 Session Overlay：

$$
Collapse(r)
\not\Rightarrow
WorkspaceRevisionChange.
$$

如果產品未來需要「團隊共享的 canonical collapsed state」，必須使用另一個 explicit collaborative presentation profile，不能重新解釋 v0.4 的 session default。

# 22. Spatial Address Classes

v0.4 將 Paper 05 的 spatial address細分為三類。

## 22.1 World Address

$$
A^{space}_{world}=(W,S,F_W,T_{o\rightarrow W}).
$$

父 region 移動後可能改變。

## 22.2 Region-relative Address

$$
A^{space}_{local}=(W,S,r,F_r,T_{o\rightarrow r}).
$$

若父 region 整體移動，但 child local placement 不變，local address 可以保持。

## 22.3 Identity-anchored Relative Address

$$
A^{space}_{rel}=(anchorID,relation,offset,frame,revisionContext).
$$

適合 layout constraint / annotation，但不替代 persistent object identity。

---

# 23. Region Path 與 Address Stability

Region path：

$$
Path(o)=(r_0/r_1/\cdots/r_n/o).
$$

path 是可解析 spatial context，不是 object identity。

Reparent 後：

$$
Path_{before}(o)\neq Path_{after}(o),
$$

但：

$$
A^{id}_{before}(o)=A^{id}_{after}(o).
$$

若 citation 需要歷史 spatial position，必須綁定 workspace/spatial revision。

---

# 24. Region Move

移動 parent region：

$$
T_{r\rightarrow parent}^{old}
eq T_{r\rightarrow parent}^{new}.
$$

子 object 的 local transform可以保持：

$$
T_{o\rightarrow r}^{old}=T_{o\rightarrow r}^{new}.
$$

但 world transform改變。

這是 nested Canvas 最重要的 compositional property。

---

# 25. Region Resize

Region intrinsic boundary resize 與 region placement resize 必須區分。

若 region boundary 本身是 intrinsic shape：

$$
ResizeBoundary(r)
\Rightarrow
NewObjectRevision(r).
$$

若只是 placement transform scale：

$$
ScalePlacement(r)
\Rightarrow
NewWorkspaceRevisionOnly.
$$

產品實作 MUST 清楚告知使用者正在做哪一種操作。

---

# 26. Region Deletion

刪除 region $r$ 時若仍有 canonical children，runtime MUST 使用 explicit strategy：

```text
reject-if-nonempty
reparent-children-keep-world
reparent-children-keep-local
cascade-tombstone
```

不得默認把 children 一起刪掉，也不得靜默丟到 world root。

`cascade-tombstone` 是高權威 lifecycle operation，必須受 capability / confirmation policy 約束。

---

# 27. v0.3 Merge Integration

Spatial changes 使用獨立 merge channel：

$$
M_P=MergePlacements(Base,Left,Right).
$$

另新增 region hierarchy / policy channel：

$$
M_G=MergeRegionGraph(Base,Left,Right).
$$

# 28. Spatial Merge Classes

## 28.1 Content Edit vs Placement Move

$$
EditIntrinsic(o)
\parallel
MovePlacement(o)
$$

SHOULD auto-merge。

## 28.2 Parent Move vs Child Local Edit

父 region move 與 child intrinsic edit SHOULD auto-merge。

## 28.3 Move vs Move Same Placement

若 normalized transform 相同，可 merge；不同則：

```text
SpatialPlacementConflict
```

## 28.4 Reparent vs Reparent

若 target parent 不同：

```text
SpatialParentConflict
```

## 28.5 Reparent vs Child Local Move

若可以 deterministic 表明 child move 是在舊 parent local frame 中完成，預設視為 conflict，除非 merge profile明確指定重放方式。

## 28.6 Parent Delete vs Child Edit

產生 lifecycle conflict：

```text
DeleteVsDescendantEditConflict
```

不得由 placement merge 自動吞掉。

---

# 29. Policy Merge

Region policy edit 必須按 policy key merge，而不是整份 map last-write-wins。

對相同 key：

- 相同值：merge；
- 一邊未改：採另一邊；
- 兩邊不同：`PolicyConflict`；
- security `deny-dominates` key MAY 使用 deterministic deny merge，但結果仍需 provenance。

---

# 30. Grammar Merge

Region grammar ID/version 若兩邊同時不同修改，預設：

```text
GrammarBindingConflict
```

不能把兩套 grammar 自動 concatenate 成新 grammar。

---

# 31. Spatial Snapshot

Region parse、semantic zoom cache、spatial query 必須綁定 canonical workspace/spatial snapshot：

$$
SnapshotID=W_{rev}.
$$

如果 runtime 使用獨立 derived spatial snapshot ID，也必須能追溯到 canonical workspace revision。

Derived spatial cache 不具 citation authority。

---

# 32. Spatial Query

例如：

$$
QueryRegion(r,filter)\rightarrow\{o_i\}.
$$

query result 可以由 R-tree/quadtree 加速，但 canonical correctness 必須只由 canonical placement / region graph 決定。

因此：

$$
IndexImplementation_1\neq IndexImplementation_2
$$

仍應得到等價 query result。

---

# 33. Nonvisual Projection

所有 authoritative region structure MUST 可序列化為 machine-readable tree/graph/list。

任何對執行或語義重要的關係不得只存在於 pixels。

因此非視覺 projection 至少可以回答：

- object 位於哪個 region；
- effective policy 是什麼；
- local grammar 是什麼；
- explicit relations 有哪些；
- unresolved candidates 有哪些；
- world/local transform 是什麼；
- execution ports 有哪些。

這也是 accessibility 與 AI tool use 的共同基礎。

---

# 34. SVG / CSS Transform Interop Boundary

SVG 2 的 nested viewport、user coordinate system、`viewBox` 與 transform composition 提供重要互通先例；CSS Transforms 則定義 web rendering transform model。

但 EveGlyph canonical spatial state 不直接依賴：

- DOM tree；
- CSS layout；
- browser px；
- SVG viewport negotiation。

Exporter / renderer adapter 可以把：

$$
T_{EGIR}
\rightarrow
T_{SVG/CSS}
$$

但 adapter MUST 明確處理 matrix convention、coordinate axis、unit 與 viewBox semantics。

Canonical spatial transform fields若進 EGIR extension record，SHOULD 使用 deterministic typed decimal/string representation，而不是 runtime binary float dump。

    "1.0", "0.0", "0.0",

  ]

# 36. Candidate Promotion

Spatial candidate：

$$
\hat e=(region,rule,src,pred,dst,confidence,snapshot,grammarVersion).
$$

Promotion：

$$
Promote(\hat e,authority)
\rightarrow
CommittedRelation+Event.
$$

如果 candidate 所依 snapshot 已不是 current base，runtime MUST：

- revalidate；
- mark stale；
- reject；

而不能直接 promotion 舊推導。

---

# 37. Region Grammar Change 與 Existing Relations

切換 grammar：

$$
G_{old}\rightarrow G_{new}
$$

不得自動刪除 existing explicit relations。

Derived candidates / caches SHOULD invalidated。

Explicit relation 若新 grammar 不支援，可以標：

```text
out-of-profile
```

但保留其 identity/history，除非 explicit migration command 決定如何轉換。

---

# 38. Semantic Zoom Cache Invalidation

Cache key SHOULD 至少包含：

$$
K_Z=Hash(
objectRevision,
projectionProfile,
zoomBand,
contextProfileVersion
).
$$

AI summary若依模型產生，還 SHOULD 包含 model / summarizer profile version。

但 cache key 本身不是 object identity。

# 39. Security Boundary

Region policy可以限制：

- runtime execution；
- external process；
- network；
- agent commit；
- cross-region execution；
- file import/export。

Capability resolution必須遵守：

$$
EffectiveCapability
\subseteq
ParentCapability.
$$

一個 child region不能只靠 local metadata 把 ancestor deny 重新變成 allow。

# 42. Compatibility with v0.3

v0.4 不要求 v0.3 canonical data migration。

原因：

1. 既有 single-world Canvas 可被視為所有 object 都在 root world frame；
2. `parent_region = null`；
3. transform 沿用既有 placement meaning；
4. 沒有 local grammar 時使用 workspace default / freeform；
5. 沒有 region policy 時繼承 workspace policy；
6. semantic zoom default 只是 identity projection；
7. 既有 explicit relations 不改 meaning。

因此：

$$
\boxed{
v0.3\rightarrow v0.4
\text{ 無 mandatory canonical migration}
}
$$

若 future writer選擇把 legacy placement 顯式 materialize 成 spatial extension records，這是 optional enrichment migration，不是必需 reinterpretation。

# 43. Eighteen Conformance Vectors

本輪附帶 18 組 machine-readable vectors。

## V1 — Nested Transform Composition

兩層 region + object local transform 得到固定 world transform。

## V2 — View Transform Non-Authority

pan/zoom 不改 workspace revision。

## V3 — KeepWorld Reparent

reparent後 world transform保持。

## V4 — KeepLocal Reparent

reparent後 local transform保持、world transform可變。

## V5 — Region Cycle Rejection

A parent B、B parent A 必須拒絕。

## V6 — Parent Move Preserves Child Local Placement

父 region移動，child local transform不變。

## V7 — Semantic Zoom Identity Preservation

zoom band切換不改 object ID/content revision。

## V8 — Deny-Dominates Policy

ancestor deny execution，child allow仍為 deny。

## V9 — Grammar Nearest Override

child explicit grammar覆蓋 inherited grammar。

## V10 — Candidate Non-Authority

spatial parser輸出不進 explicit relation heads。

## V11 — Cross-Region Proximity Isolation

不同 region 的近距離 object不自動產生 proximity relation。

## V12 — Explicit Cross-Region Connector

explicit relation跨 region仍保持有效。

## V13 — Reparent Is Placement Mutation

純 reparent不改 intrinsic content hash。

## V14 — Move-vs-Move Conflict

兩 branch對同 placement不同 transform產生 conflict。

## V15 — Content Edit + Region Move Auto-Merge

intrinsic edit與region placement move可合併。

## V16 — Region Delete vs Child Edit Conflict

不得自動 cascade吞掉 child edit。

## V17 — Session Collapse Non-Canonical

collapse/expand不產生 workspace revision。

## V18 — Execution Export Port Required

跨 executable region依賴若無 export/import port必須拒絕 compilation。

# 44. Design Freeze

完成 v0.4 後，後續 v0.5–v1.0 不得在未顯式升版 / migration 的情況下破壞：

1. region 是 first-class object；
2. canonical spatial parent至多一個；
3. region parent graph必須 acyclic；
4. graph relations與 spatial parentage分離；
5. World / Region / Object-local / View frames分離；
6. column-vector homogeneous affine convention固定；
7. canonical transform 表示 local-to-parent；
8. nested composition order固定；
9. view transform不具 canonical authority；
10. KeepWorld / KeepLocal reparent必須顯式區分；
11. pure reparent預設不改 intrinsic content；
12. geometry containment不自動建立 canonical membership；
13. semantic scope不自動等於 spatial parent；
14. policy inheritance只使用版本化 deterministic resolver classes；
15. child capability不能突破 ancestor deny；
16. local grammar可以不同；
17. grammar composition必須 explicit profile；
18. region parser只產生 candidate；
19. derived relation預設不跨 region；
20. explicit relation可以跨 region；
21. cross-region execution需要 boundary contract / ports；
22. semantic zoom是 projection；
23. AI summary未 commit前是 derived cache；
24. collapse/expand預設是 session state；
25. world/local spatial addresses分離；
26. region path不是 object identity；
27. region move可以保持 descendant local transform；
28. region deletion strategy必須 explicit；
29. spatial merge與 intrinsic merge分 channel；
30. move-vs-move可產生 first-class conflict；
31. grammar/policy simultaneous incompatible edits不得 silent merge；
32. spatial indexes是 acceleration structures；
33. authoritative spatial structure必須有 nonvisual serialization；
34. SVG/CSS只作 adapter/projection reference；
35. v0.4不修改 `egir-cj/0.1`；
36. v0.3到v0.4無 mandatory canonical migration。

# 46. 結論

v0.4 將 Infinite Canvas 從：

$$
\text{one flat plane with draggable nodes}
$$

提升為：

$$
\boxed{
\text{Nested Coordinate Space}
+
\text{Local Policy}
+
\text{Local Grammar}
+
\text{Explicit Authority Boundary}
}
$$

一個 region可以被移動而不破壞 child local placement；一個 child可以 reparent而保持 world position；不同 region可以擁有不同 grammar；semantic zoom可以改呈現但不改 object；跨 region relation可以存在，但 proximity不能偷渡 semantic edge；execution則必須經 typed boundary composition。

所以 v0.4 完成後，EveGlyph 的 Canvas不再只是「畫布功能」，而具有真正可交接的 spatial-language contract。

下一輪進入：

$$

}
$$
