# 1. 本輪問題

Paper 03 已經建立 Native Computational Mathematics 的核心原則：數學不是 LaTeX 字串，binding、type/domain、assumptions、constraints、units、exactness、execution、proof/evidence 與 presentation 必須分離。

TW-01 的 `ncm/0.1` 又證明最小 $x^2\rightarrow2x$ vertical slice 可以直接消費 native object，不需要先輸出 LaTeX 再重新 parse。

但若現在直接把這個最小 slice 交給本地端長期擴充，仍會遇到一組高風險問題：

1. 每多一個 operator 是否就新增 AST node？
2. bound variable identity 是名字、node ID，還是 scope slot？
3. exact decimal 與 approximate decimal 如何不被混用？
4. assumptions 與 rewrite side conditions 如何保存？
5. undefined、conditional、unresolved、unevaluated 是否只是 generic error？
6. CAS 說兩式相等，與 theorem prover 證明相等是否同一件事？
7. presentation edit 是否會偷換 mathematical equality？
8. subexpression address 在 rewrite 後如何追蹤？
9. MathML、OpenMath、SMT-LIB、LaTeX 如何互通但不接管 canonical ontology？
10. 本地端未來如何加入 CAS/prover，而不重設 NCM？

v0.5 的目的，就是把這些問題壓成一個 **stable math object candidate profile**。

---

# 2. 核心策略：Small Semantic Kernel

v0.5 不採「每一種數學概念都是 core node kind」的設計。

若核心直接包含：

```text
sin
cos
derivative
integral
group-operation
matrix-product
forall
exists
limit
laplacian
...
```

那麼每新增一門數學或一個 domain，都可能造成 schema 升版。

v0.5 採：

$$
\boxed{
\text{Small Structural Kernel}
+
\text{Versioned Semantic Symbol Registry}
}
$$

結構核心只負責「如何組成一個數學物件」；運算的領域含義由 semantic symbol reference 決定。

因此：

$$
Apply(op,args)
$$

中的 $op$ 可以指向：

- EveGlyph native symbol registry；
- OpenMath content dictionary symbol；
- workspace-local mathematical declaration；
- external theory registry；
- prover/backend-specific symbol adapter。

這使 NCM 可以擴張數學語言，而不把 core schema 變成無限 operator enumeration。

# 3. Native Math Object

一個 v1 candidate math intrinsic state 定義為：

$$
M=
(
role,
G,
Env,
A,
C,
T,
U,
N,
P,
E,
R,
X
).
$$

其中：

- $role$：object role；
- $G$：expression graph；
- $Env$：declaration / theory environment；
- $A$：assumptions；
- $C$：constraints / obligations；
- $T$：type/domain assertions；
- $U$：unit/dimension assertions；
- $N$：numeric policy；
- $P$：presentation plan；
- $E$：evidence records；
- $R$：result state；
- $X$：execution bindings / profile。

Canonical profile marker：

```json
{
  "profile": "ncm/1.0-candidate.1"
}
```

# 4. Math Object Roles

v0.5 定義：

```text
expression
definition
claim
computation-result
proof-artifact
constraint-set
```

`role` 不替代 object `kind="math"`；它描述 math intrinsic 的用途。

例如：

$$
O_i.kind=math
$$

而：

$$
M_i.role=claim.
$$

同一 persistent object lineage MAY 從 draft expression 經 explicit semantic edit 轉為 claim，但這是 intrinsic content mutation，必須建立新 revision。

---

# 5. Expression Graph

Expression graph：

$$
G=(N,E,r).
$$

其中 $r$ 是 root node ID。

v0.5 committed graph MUST：

- node IDs unique；
- 所有 node references 可解析；
- graph 無 expression cycle；
- 所有 canonical nodes 從 root reachable；
- node array 以 node ID lexical order canonicalize；
- 不靠 array insertion order 表達 graph identity。

Recursive definitions MUST 透過 declaration/reference 建立，不以 expression graph 自我 cycle 表示。

# 6. Core Node Kinds

`ncm/1.0-candidate.1` 的 structural kernel 定義以下 node kinds。

## 6.1 `free-ref`

指向 environment declaration：

```json
{
  "id": "n1",
  "kind": "free-ref",
  "declaration_id": "d-x"
}
```

Visible name 不等於 variable identity。

## 6.2 `bound-ref`

```json
{
  "id": "n2",
  "kind": "bound-ref",
  "binding_id": "b-x"
}
```

Bound reference MUST resolve 到 enclosing binder 的 binding slot。

## 6.3 `integer`

```json
{
  "id": "n3",
  "kind": "integer",
  "value": "12345678901234567890"
}
```

Integer 使用 decimal string，避免 host-language integer width 進入 canonical semantics。

## 6.4 `rational`

```json
{
  "id": "n4",
  "kind": "rational",
  "numerator": "1",
  "denominator": "3"
}
```

Canonical rational MUST：

$$
\gcd(|p|,q)=1,
$$

$$
q>0.
$$

若 $p=0$，則：

$$
q=1.
$$

## 6.5 `decimal-exact`

Exact decimal 以 coefficient / exponent10：

```json
{
  "id": "n5",
  "kind": "decimal-exact",
  "coefficient": "123",
  "exponent10": "-2"
}
```

表示：

$$
123\times10^{-2}.
$$

它不是 binary float。

## 6.6 `number-approx`

```json
{
  "id": "n6",
  "kind": "number-approx",
  "format": "decimal",
  "value": "0.333333",
  "precision": {
    "kind": "absolute-error",
    "value": "0.000001"
  }
}
```

Approximate number MUST 帶 approximation metadata 或明確 `unknown-error`。

## 6.7 `apply`

```json
{
  "id": "n7",
  "kind": "apply",
  "operator": {
    "namespace": "eveglyph",
    "theory": "eg.math.arithmetic",
    "name": "power",
    "version": "1"
  },
  "args": ["n1", "n3"]
}
```

Operator meaning 由 semantic reference 決定。

## 6.8 `binder`

Binder 是 core structural node，因為 scope 不是一般 application 可以安全替代的結構。

```json
{
  "id": "n8",
  "kind": "binder",
  "operator": {
    "namespace": "eveglyph",
    "theory": "eg.math.calculus",
    "name": "integral",
    "version": "1"
  },
  "bindings": [
    {
      "binding_id": "b-x",
      "display_name": "x",
      "domain": null
    }
  ],
  "body": "n7",
  "limits": {
    "lower": "n-zero",
    "upper": "n-one"
  }
}
```

## 6.9 `sequence`

用於 ordered tuple/list-like semantic container。

## 6.10 `matrix`

保存 rows/columns 與 node references；matrix shape 是 structural fact，不由 renderer grid 推測。

## 6.11 `piecewise`

每一 case：

$$
(condition,value).
$$

`otherwise` MAY 缺省；缺省不代表自動 undefined，result semantics 由 validator/evaluator 決定。

## 6.12 `quantity`

```json
{
  "id": "nq",
  "kind": "quantity",
  "value": "n-value",
  "unit": {
    "namespace": "eveglyph",
    "theory": "eg.units.si",
    "name": "metre",
    "version": "1"
  }
}
```

Unit 不是 presentation suffix。

## 6.13 `external-ref`

指向另一個 versioned math object 或 subobject address。

## 6.14 `hole`

表示 intentionally incomplete / unresolved expression position。

Committed `hole` MUST 帶 status/reason，不得被 formatter 自動填值。

# 8. Environment 與 Free Declarations

Environment：

```json
{
  "theory": {
    "namespace": "eveglyph",
    "theory": "eg.math.real-analysis",
    "name": "context",
    "version": "1"
  },
  "declarations": [
    {
      "declaration_id": "d-x",
      "display_name": "x",
      "type": {
        "namespace": "eveglyph",
        "theory": "eg.math.types",
        "name": "Real",
        "version": "1"
      }
    }
  ]
}
```

Free variable identity 由 `declaration_id` 定義；display name 可變。

因此：

$$
RenameDisplay(x\rightarrow y)
$$

不必改 mathematical binding identity。

# 9. Binder 與 Alpha-Equivalence

考慮：

$$
\int_0^1x^2\,dx
$$

與：

$$
\int_0^1y^2\,dy.
$$

若 binder structure、operator、domain、body mapping 相同，只是 bound display name 不同，則：

$$
M_1\equiv_{\alpha}M_2.
$$

v0.5 alpha-equivalence MUST 忽略：

- `binding_id` 的任意 lexical spelling；
- bound variable `display_name`；

但 MUST 保留：

- binder nesting；
- binding slot cardinality/order；
- operator semantic identity；
- body references；
- limits/domain；
- free declarations。

Substitution MUST be capture-avoiding by construction。

# 10. Type 與 Domain

v0.5 不強迫所有 math object 都立即完全 typed。

Type state 可以是：

```text
explicit
verified
unknown
```

Candidate type inference 不直接進 authoritative type assertion；它應留在 ASCS candidate layer，直到被 deterministic checker 或 explicit authority commit。

Type assertion：

```json
{
  "node": "n7",
  "status": "verified",
  "type": {
    "namespace": "eveglyph",
    "theory": "eg.math.types",
    "name": "Real",
    "version": "1"
  },
  "evidence_ref": "ev-type-01"
}
```

同一 visible operator 在不同 type/domain 可以具有不同 semantics。

因此：

$$
+_{\mathbb Z}
\neq
+_{Matrix}
$$

在 operator resolution 層必須可區分。

# 11. Assumptions 與 Constraints

## 11.1 Assumption

Assumption 是 context 中已接受的 premise：

$$
A=\{a_1,\ldots,a_n\}.
$$

例如：

$$
x>0.
$$

## 11.2 Constraint

Constraint 是尚需滿足、驗證或追蹤的 obligation / side condition：

$$
C=\{c_1,\ldots,c_m\}.
$$

例如 rewrite：

$$
\frac{x}{x}\rightarrow1
$$

必須帶：

$$
x\neq0.
$$

因此：

$$
\boxed{
Assumption\neq Constraint
}
$$

Constraint status：

```text
pending
discharged
violated
unknown
```

Constraint 被 discharged MUST 保留 evidence；不能只刪掉 side condition。

---

# 12. Exact 與 Approximate Numerics

v0.5 將 numeric state 分成：

```text
exact
approximate
interval/uncertainty via semantic profile
```

Exact integer/rational/decimal 不得因 projection 變成 approximate intrinsic value。

例如：

$$
\frac13
$$

投影為：

$$
0.333333
$$

不得造成：

$$
Exact(1/3)\rightarrow Approx(0.333333)
$$

的 silent canonical mutation。

Approximate equality：

$$
a\approx_{metric,\epsilon}b
$$

不得提升為 theorem equality。

---

# 13. Numeric Policy

Math object MAY 保存 execution-oriented numeric policy：

```json
{
  "mode": "exact-preferred",
  "approximation": "explicit-only",
  "default_precision_digits": 50,
  "rounding": "nearest-even"
}
```

這是 execution policy，不是 mathematical theorem。

Backend MAY 拒絕不支援的 policy，但 MUST typed-fail，而不能偷偷改成 host default float。

---

# 14. Units 與 Dimensions

`quantity` node 保存 unit semantic ref。

另可附 dimension assertion：

```json
{
  "node": "nq",
  "dimension": {
    "L": "1",
    "T": "-1"
  },
  "status": "verified",
  "evidence_ref": "ev-dim-01"
}
```

Dimension exponent 使用 rational-compatible string。

對：

$$
3\,m+5\,s
$$

若 operation 要求同 dimension，validator 應得到 typed incompatibility，而不是先做 numeric addition 再把單位拼回去。

Unit conversion 必須是 explicit semantic transform，有 conversion source/evidence。

# 15. First-Class Result States

Evaluation result MUST 區分：

```text
defined
conditional
undefined
unresolved
unevaluated
```

## 15.1 Defined

有合法 value root。

## 15.2 Conditional

$$
Result=(value,conditions).
$$

## 15.3 Undefined

有 reason code，例如：

```text
division-by-zero
outside-domain
branch-undefined
singularity
```

不得一律 collapse 成 NaN。

## 15.4 Unresolved

存在多個 interpretation / operator / type candidates，無足夠 authority 消歧。

## 15.5 Unevaluated

表達式合法，但 backend/resource/policy 未執行或無法執行。

# 16. Evidence Classes

v0.5 凍結：

```text
assumed
computed
verified
proved
heuristic
external
```

$$
\boxed{
Computed\neq Proved
}
$$

Evidence record：

```json
{
  "evidence_id": "ev-01",
  "class": "computed",
  "producer": {
    "kind": "cas",
    "name": "example-cas",
    "version": "1.0"
  },
  "event_ref": "urn:uuid:...",
  "inputs": [],
  "conditions": [],
  "certificate_ref": null
}
```

`proved` MUST 指向：

- proof object；或
- certificate + verifier identity/version。

只有「CAS 回傳 true」不得直接標成 `proved`。

# 17. Equality Family

v0.5 正式凍結：

```text
surface
structural
alpha
definitional
theorem
approximate
```

## Surface

依指定 projection 比較。

## Structural

expression graph structural equality。

## Alpha

binder-renaming invariant equality。

## Definitional

依明確 theory/reduction policy 得到同 normal form。

## Theorem

存在：

$$
\pi:\Theta\vdash M_1=M_2.
$$

## Approximate

依 metric/tolerance。

任何 equality verdict MUST 說明 equality class。

禁止只回：

```text
"equal": true
```

而沒有 comparison semantics。

# 18. Canonicalization 仍不等於 Simplification

`egir-cj/0.1` 只負責 deterministic bytes。

NCM candidate profile 額外要求 structural records 的排序／正規形式，但不允許 canonicalizer 使用 mathematical theorem 改寫 expression。

因此：

$$
a+b
$$

與：

$$
b+a
$$

即使在某 commutative theory 下 theorem-equivalent，也不要求 content hash 相同。

$$
\boxed{
ContentEquality\neq MathematicalEquality
}
$$

---

# 19. NCM Structural Canonical Rules

對 `ncm/1.0-candidate.1`：

1. `expression.nodes` 按 node `id` lexical order；
2. `environment.declarations` 按 `declaration_id` lexical order；
3. type assertions 按 `(node,status)` lexical order；
4. unit/dimension assertions 按 node ID lexical order；
5. assumptions / constraints 按 record ID lexical order；
6. evidence records 按 `evidence_id` lexical order；
7. graph edge order由 node fields 明確定義；
8. `apply.args` order 具有語義，MUST 保留；
9. binder binding slot order 具有語義，MUST 保留；
10. rational 必須 canonical reduced form；
11. exact decimal lexical form必須 canonical；
12. Unicode display labels 不自動 NFC/NFKC normalize。

這些規則只對 candidate profile 的合法 intrinsic layout 生效，不修改 `egir-cj/0.1` 本身。

# 20. Rewrite Contract

Math rewrite：

$$
r:(L\rightarrow R)\mid C.
$$

Transformation record MUST 保存：

- input version address；
- input subaddress；
- output version address；
- output subaddress；
- rule semantic ref；
- side conditions；
- evidence class；
- backend/checker version；
- old→new node mapping when available。

Rewrite 不得以「改完的字串」作唯一 provenance。

---

# 21. Subexpression Addressing

v0.5 使用：

$$
A^{math-sub}=(A^{ver},nodeID).
$$

`nodeID` 是 **revision-local identifier**，不是跨 revision persistent identity。

因此：

$$
A^{math-sub}_{v_1}
$$

不能未驗證直接套到 $v_2$。

Rewrite mapping：

$$
MapNode(v_1,n_i,v_2)
\rightarrow
\{n_j,Deleted,Split,Merged,Ambiguous,Unmapped\}.
$$

如果某 subexpression 真的需要跨 revision persistent identity，MAY 將其提升為獨立 ASCS object，而不是濫用 node ID。

    "derivative_style": "leibniz"

$$
PresentationChange
\not\Rightarrow
SemanticInequality.
$$

因此 semantic equality 不能以 content hash 取代。

# 24. Computation Contract

$$
Eval(M,\Gamma,\Pi)
\rightarrow
(R,\Delta,\rho,\chi).
$$

Backend declaration MUST 至少提供：

- backend name；
- backend version；
- supported theory/profile；
- numeric policy support；
- proof/evidence capability；
- resource policy。

不支援時回 typed state：

```text
UnsupportedTheory
UnsupportedNode
UnsupportedNumericPolicy
ResourceLimit

```

禁止 silently fallback 到不同 semantics。

# 25. Proof / Prover Contract

v0.5 不試圖定義 universal proof language。

它只凍結 proof boundary：

$$
ProofArtifact
\xrightarrow{Verifier(version,theory)}
VerifiedEvidence.
$$

Proof backend 可以是 Lean、Coq、Isabelle、SMT solver certificate、specialized checker 或未來其他 proof engine。

但 EveGlyph canonical claim 不以「某 backend 的 UI 顯示成功」作 proof ontology。

Proof evidence MUST 指出 verifier/theory/profile。

# 26. CAS Contract

CAS backend MAY：

- simplify；
- differentiate；
- integrate；
- factor；
- solve；
- numeric evaluate；
- transform matrices；
- emit conditions。

但所有 CAS transform 必須：

$$
InputRevision
\rightarrow
Result/DerivedRevision
+
Evidence
+
Conditions.
$$

CAS output 不得默認覆寫 source identity。

# 27. Adapter Fidelity Matrix

一般 TW-01 adapter fidelity 太粗，不足以描述數學互通。

v0.5 新增 math-specific fidelity matrix：

```json
{
  "semantics": "exact",
  "binding": "exact",
  "conditions": "preserved-subset",
  "presentation": "approximated",
  "provenance": "dropped"
}
```

```text
exact
preserved-subset
approximated
dropped
unknown
not-applicable
```

Coarse TW-01 fidelity 可以由此導出，但不能反向假設所有維度都一樣。

# 28. LaTeX Adapter

LaTeX 主要是 source / presentation adapter。

Import：

$$
LaTeX
\rightarrow
CandidateNCM.
$$

Export：

$$
NCM
\rightarrow
LaTeXProjection.
$$

Macro、implicit multiplication、custom commands、ambiguous notation 可能造成 semantics fidelity 降低。

因此 LaTeX round-trip：

$$
Export(Import(s))=s
$$

不是 mandatory semantic criterion。

# 29. MathML Adapter

截至 2026-08-25，W3C MathML 4 最新公開 Working Draft 為 2026-06-04；MathML Core 為 2025-06-24 Candidate Standard。

NCM adapter MUST 區分：

- presentation-oriented import/export；
- content-oriented semantic subset；
- browser-renderable MathML Core projection。

Presentation MathML 的視覺結構不得自動被宣稱為完整 NCM semantics。

# 30. OpenMath Adapter

OpenMath 官方 normative standard 仍為 Version 2.0 Revision 2。

OpenMath semantic symbols/content dictionaries 對 NCM 的 semantic symbol registry 是重要 interoperability reference。

對 supported subset：

$$
NCM_{subset}
\leftrightarrow
OpenMath
$$

SHOULD 儘可能保持 semantics / binding。

但 EveGlyph persistent identity、workspace revision、Canvas placement、execution provenance 不屬 OpenMath formula ontology，不應強塞進 OpenMath object 本體。

# 31. OMDoc Adapter Boundary

NCM v1 candidate 可將：

- claim；
- definition；
- theory ref；
- proof artifact；

映射到 OMDoc-compatible structures。

但 ASCS workspace identity/history/runtime authority 仍屬 EveGlyph 層。

# 32. SMT-LIB Adapter Boundary

SMT-LIB 2.7 是 solver interoperability 的重要 subset target。

對 SMT-compatible typed logical expression：

$$
NCM_{SMT-subset}
\rightarrow
SMTLIB.
$$

Solver result：

```text
sat
unsat
unknown
```

不能直接對應：

```text
proved
```

除非 verifier/evidence profile 明確定義 certificate/proof semantics。

---

# 33. Undefined / NaN / Infinity Boundary

Host-language `NaN`、`Infinity` 不得被偷換為所有數學 undefined states。

例如：

$$
\frac10
$$

在不同 theory/domain 中需要明確 result semantics。

因此：

$$
Undefined(reason)
\neq
IEEE754NaN.
$$

若 backend 使用 IEEE floating representation，只能作 physical/numeric backend detail。

---

# 34. Unknown 是合法狀態

v0.5 明確允許：

- unknown type；
- unresolved symbol；
- unresolved branch convention；
- unknown equality；
- pending constraint；
- unevaluated expression；
- unknown adapter fidelity dimension。

AI 不得因為 canonical schema 不喜歡空白，就自行補成看似完整的數學事實。

$$
\boxed{
Unknown\neq False\neq Error
}
$$

# 35. Candidate Authority Boundary

AI、OCR、LaTeX parser、spatial math parser、CAS heuristic 均可能產生候選 interpretation。

它們預設：

$$
Candidate
\notin
CommittedMathSemantics.
$$

只有經：

$$
Proposal
\rightarrow
Validation
\rightarrow
Authority
\rightarrow
Commit
$$

才成為 canonical NCM revision。

---

# 36. `ncm/0.1` Compatibility

既有 `ncm/0.1` 仍合法。

v0.5 reader MUST 能辨識：

```text
ncm/0.1
ncm/1.0-candidate.1
```

但不得以 candidate semantics 重新解釋舊 `ncm/0.1` bytes。

對可映射的 legacy object，可執行 explicit enrichment migration：

$$
ncm/0.1
\xrightarrow{Migrate}
ncm/1.0-candidate.1.
$$

這會建立新的 object revision，保持 persistent identity，並保存 migration event。

因 intrinsic representation 改變：

$$
A^{content}_{old}\neq A^{content}_{new}
$$

通常是正常的。

---

# 37. No Mandatory Canonical Migration

ASCS v0.5 不要求既有 workspace 立即升級所有 math objects。

因此：

$$
\boxed{
v0.4\rightarrow v0.5
\text{ requires no mandatory canonical migration}
}
$$

Legacy NCM object 可以與 candidate profile object 共存在同一 ASCS workspace，只要 runtime/profile negotiation 正確。

---

# 38. Promotion to v1.0

在 v1.0 handoff 前，candidate profile 必須經 v0.5--v0.9 integration feedback。

若無 breaking semantic change，v1.0 可以發布：

```text
ncm/1.0
```

並宣告與 candidate.1 `Exact` compatibility。

若發現 breaking change，必須先發布：

```text
ncm/1.0-candidate.2
```

並提供 explicit migration；禁止在 `candidate.1` identifier 下改語義。

# 40. Thirty Core Invariants

## M1 — Math object is not source text

$$
NCM\neq LaTeXString.
$$

## M2 — Small kernel

Domain operators不得靠無限 core node kinds 擴張。

## M3 — Semantic symbol identity

Visible glyph/name 不得單獨決定 operator identity。

## M4 — Graph references valid

Committed graph 無 dangling node ref。

## M5 — Expression graph acyclic

Recursive definitions用 declaration/reference 表達。

## M6 — Free declaration identity

Free variable identity 與 display name 分離。

## M7 — Bound identity structural

Bound variable 不靠 visible name 綁定。

## M8 — Alpha-equivalence first-class

Binder rename 不等於 semantic edit。

## M9 — Capture avoidance

Substitution 不得 capture free variables。

## M10 — Type unknown valid

Unknown type 是合法狀態。

## M11 — Assumption/constraint separation

Accepted premise 不等於 pending obligation。

## M12 — Constraint evidence preservation

Discharged condition 必須保存 evidence。

## M13 — Exact integer unbounded

不得依賴 host integer width。

## M14 — Rational canonicality

Reduced form + positive denominator。

## M15 — Exact decimal non-float

Exact decimal 不依賴 IEEE binary float。

## M16 — Approximation explicit

Approximate number 必須標 precision/error state。

## M17 — Exact/approx equality separation

Approximate equality 不得提升 formal equality。

## M18 — Units semantic

Unit/dimension 不是字串後綴。

## M19 — Undefined first-class

Undefined 不 collapse 成 generic error / NaN。

## M20 — Conditional first-class

Result condition 不得靜默丟失。

## M21 — Unresolved first-class

多解 interpretation 可被 canonical 保存。

## M22 — Evidence class explicit

Computed、verified、proved、heuristic 不得混用。

## M23 — Proved requires verifier evidence

`proved` 不能只有 backend success string。

## M24 — Equality typed

所有 equality verdict 指定 equality class。

## M25 — Canonicalization is not simplification

Hash canonicalization 不用 theorem 改寫 expression。

## M26 — Node address revision-aware

Node ID 不是跨 revision persistent identity。

## M27 — Rewrite provenance

Rewrite 必須保存 rule/conditions/evidence/mapping。

## M28 — Adapter fidelity multidimensional

Math adapter 不用單一 lossless/lossy 掩蓋 binding/conditions/provenance 差異。

## M29 — Candidate non-authority

AI/parser/CAS heuristic candidate 不直接成 canonical semantics。

## M30 — Legacy no silent reinterpretation

`ncm/0.1` 不以 candidate profile 規則重新解讀。

# 41. 本地端 Handoff Minimum

未來本地端要宣稱支援 `ncm/1.0-candidate.1`，至少必須能：

1. parse/profile validate math object；
2. validate graph refs / reachability / cycles；
3. canonicalize rational/decimal records；
4. distinguish free/bound refs；
5. test alpha-equivalence；
6. preserve assumptions/constraints；
7. preserve exact/approx numerics；
8. validate units/dimensions at least structurally；
9. return typed result states；
10. record evidence classes；
11. preserve rewrite provenance；
12. resolve revision-local subaddresses；
13. expose adapter fidelity matrix；
14. support legacy `ncm/0.1` without reinterpretation；
15. run conformance vectors before claiming compatibility。

CAS/prover backend 本身 MAY 尚未完整，但 object contract 不得因此被改寫成 backend-specific AST。

# 46. 非主張

# 48. 結論

v0.2 解決 contract。

v0.3 解決 history。

v0.4 解決 space。

v0.5 開始把可計算內容本身壓成穩定 native object：

$$
\boxed{
\text{Formula String}
\rightarrow
\text{Versioned Mathematical Object}
}
$$

這個 object 不只知道「長什麼樣」，而知道：

- 哪些符號是 free / bound；
- 依賴什麼 theory；
- 有哪些 assumptions；
- 哪些 side conditions 尚未 discharge；
- 數值是 exact 還是 approximate；
- 單位／dimension 是什麼；
- 結果 defined、conditional、undefined、unresolved 或 unevaluated；
- 這個結果是 computed、verified 還是 proved；
- rewrite 是由哪條 rule、哪個 backend、哪些 conditions 得到；
- 目前畫面只是 projection，還是真正 mathematical structure。

因此：

$$
\boxed{
NCM_{v1-candidate}
=
Structure
+Binding
+Context
+Conditions
+Numerics
+Evidence
+Interop
}
$$

下一輪 v0.6 不再重新碰數學 ontology，而是把 custom glyph / GSC / semantic symbol 可靠接到這個已凍結的 semantic target 上。
