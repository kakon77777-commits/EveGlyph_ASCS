# 1. 問題定義

到 v0.8 為止，ASCS 已經能回答：object 是什麼、如何版本化、如何存在 Canvas、如何表達 Native Math / Glyph、AI 如何提出 proposal、legacy ecosystem 如何透過 adapter 進出。

但這仍不足以直接交給長期 implementation team。缺少 operational freeze 時，本地端很容易在真正實作過程中重新發明：

- 哪些資料可信；
- 哪些資源必須限制；
- crash 後誰是 source of truth；
- log / trace 能不能改變 canonical state；
- 為什麼某次 resolve / mutation / execution 成立；
- benchmark 在哪台機器、哪個 dataset 上才有意義；
- release 包需要什麼證據；
- migration 是否可 dry-run / restart / rollback；
- rollback 是否會偷偷丟新版本資料；
- compatibility 到底驗哪些 profile 組合。

v0.9 的目的就是把這些工程自由度壓縮成可交接契約。

# 2. Operational State Model

v0.9 延續 TW-03：

$$
RuntimeState=C\cup S\cup D\cup X
$$

其中：

- $C$：Canonical State；
- $S$：Session Overlay；
- $D$：Derived Cache / Index / Telemetry source；
- $X$：External Effects / External Systems。

Product hardening 的第一條規則仍是：

$$
\boxed{D\not\Rightarrow C,\qquad X\not\Rightarrow C.}
$$

任何 cache、telemetry、OS path、process status、network response 都不能因「production implementation 方便」而重新升格成 object identity 或 canonical truth。

# 4. Security Boundary

## 4.1 Default Deny

Production operational policy MUST default deny capabilities that touch external state：

$$
Allowed(a,e)=Capability(a,e)\land Policy(a,e).
$$

缺 capability、未知 capability、未知 critical policy 都是 deny。

## 4.2 Trust Zones

至少區分：

1. validated canonical records；
2. session/UI input；
3. derived caches/indexes；
4. adapter/import input；
5. external filesystem/process/network；
6. telemetry/observability backend。

Legacy/import input 與 external world MUST 預設 untrusted。

## 4.3 Secret Boundary

Secrets MUST NOT：

- 進 portable provenance；
- 進 canonical object content；
- 進 normal telemetry payload；
- 以 plaintext persistent browser storage 滿足 production profile；
- 因 debug export 被打包進 release。

Production SHOULD 使用 OS keychain 或明確 external secret provider。

## 4.4 Current Editor Migration

目前 EveGlyph Editor 的 localhost gate、workspace confinement、agent timeout、diff review 都是可沿用的 development primitives；但 plaintext localStorage API keys、auto-approve CLI、destructive Reject、elevated `.eveglyph/rules.md` 與 raw local diagnostic samples 都必須在 production handoff 中重新經過 v0.7/v0.9 policy 化。

# 5. Resource Limits

Resource limits 分兩類：

$$
Limit=Hard\cup Soft.
$$

Hard limit 是 safety / stability boundary，超限 MUST typed reject：

$$
HardExceeded\rightarrow ResourceLimitExceeded.
$$

Soft budget 是 performance / UX boundary，可 defer、virtualize、degrade 或要求確認，但不得為了達標修改 canonical semantics。

## 5.1 Mandatory bounded surfaces

Production profile 至少必須能限制：

- decoded workspace bytes；
- object / relation materialization；
- adapter decoded expansion；
- dictionary/dependency bytes；
- context-pack bytes；
- agent runtime；
- execution/rewrite/proof step budgets；
- external processes；
- network requests / concurrency；
- render materialized nodes；
- telemetry buffer / file size。

---

# 6. Performance Classes

v0.9 定義四個宣告類別：

```text
P0-conformance
P1-local-interactive
P2-authoring-medium
P3-stress-observed
```

性能結論只有在環境與 dataset 被 pin 時成立：

$$
BenchmarkResult=f(Build,Environment,Dataset,Workload).
$$

所以不允許只寫「EveGlyph 可支援十萬節點」而沒有硬體、runtime、dataset、viewport workload 與 measurement method。

P1 / P2 的 reference latency targets 是 handoff budgets，不是宇宙常數。實作者 MAY 提供更好的 profile，但不得悄悄降低 declared class 還宣稱原 class PASS。

---

# 7. Crash / Recovery Contract

Crash recovery MUST 從已提交 canonical/storage evidence 重建：

$$
CommittedEGStore
\rightarrow Validate
\rightarrow RehydrateEGIR
\rightarrow RebuildDerived.
$$

不得從 stale cache、render tree、telemetry log 或 AI 推測重建 canonical state。

## 7.1 Unknown External Effect

若 external effect 的 outcome 在 crash 時未知：

$$
Outcome=Unknown.
$$

MUST NOT automatic replay，除非該 effect profile 明確宣告 idempotent 且 replay policy 明確允許。

## 7.2 Degraded Is Legal

缺 chunk、缺外部依賴、索引需重建時，可以進：

```text
Degraded
Unavailable
ManualRecovery
Conflict
Unknown
```

而不是製造「看起來成功」的替代資料。

---

# 8. Observability

$$
\boxed{Telemetry\neq CanonicalState.}
$$

Telemetry MAY 包含 trace / metric / log，但：

- telemetry backend 不可用時，local canonical editing MUST 繼續；
- telemetry identifier 不得變成 persistent object ID；
- sampling / rotation / exporter replacement 不改 workspace semantics；
- production exporter MUST redact secrets 並宣告 retention；
- absolute path / raw model sample 應最小化或 hash/redact。

OpenTelemetry 可以作 vendor-neutral exporter reference，但不是 EveGlyph canonical ontology。

# 9. Explainability APIs

v0.9 正式凍結：

$$
ExplainResolution(reference)
$$

$$
ExplainMutation(commandID)
$$

$$
ExplainExecution(resultID)
$$

## 9.1 ExplainResolution

必須能回答：

- 參照類型與 base context；
- resolver profile/version；
- 查到哪些 candidate；
- 為什麼選這個結果；
- ambiguity / unauthorized / stale / unavailable 原因；
- 哪些 locator 因 policy 被隱藏。

## 9.2 ExplainMutation

必須能回答：

- 誰提出 command；
- base workspace revision；
- preconditions；
- validator / capability / policy gates；
- conflict / rebase / branch decision；
- 寫出哪些 object/revision/event；
- 是否產生 external-effect intent。

## 9.3 ExplainExecution

必須能回答：

- input revisions；
- operator / glyph binding resolution；
- assumptions / constraints；
- backend/version；
- execution capability；
- result identity/revision；
- conditions / undefined state；
- evidence class。

其中：

$$
Computed\neq Verified\neq Proved.
$$

# 10. Diagnostics vs Explanation

Diagnostic 是「系統目前觀察到什麼問題」；Explanation 是「某個決策為什麼成立」。

$$
Diagnostic\neq Explanation.
$$

Diagnostic 可以是 transient；Explain record 應能從 canonical provenance / policy evidence 重建。兩者都不得包含 secret plaintext。

---

# 11. Benchmark Matrix

每份正式 benchmark report MUST pin：

- build/release ID；
- OS/runtime；
- CPU/memory/GPU（如相關）；
- dataset ID + SHA-256；
- object/relation counts；
- workload/seed；
- warm/cold cache condition；
- metric definitions；
- repetitions / percentile method。

Storage 仍沿用 TW-02：

$$
(CR,RA,WA,MR,DR,T_e,T_d,M_{peak}).
$$

Canvas/runtime 另量：frame latency、resolve latency、transaction latency、materialization count、cache metrics。

Agent/runtime 另量：context bytes、run duration、proposal size、validation/commit duration、external effect count。

# 12. Packaging Layout

v1.0 handoff 的 implementation release SHOULD 至少有：

```text
specs/
schemas/
examples/
conformance/
tools/
benchmarks/
migrations/
release/

```

Specification-only package 可以保留目前 roadmap layout，但同樣必須有 machine-readable support、validator、SHA manifest 與 release index。

不得打包：

- secrets/tokens；
- bytecode caches；
- temporary worktrees；
- private absolute-path state；
- stale benchmark output 冒充 current evidence；
- unchecked generated artifacts。

# 13. SBOM / Supply Chain Provenance

真正 production binary/source distribution MUST 產生 dependency inventory / SBOM。v0.9 以 stable SPDX 3.0 family 作互通 reference；若供應鏈 pipeline 支援，MAY 產生 SLSA provenance/attestation。

但：

$$
SBOMID\neq ObjectID,
$$

$$
SLSAAttestation\neq WorkspaceRevision.
$$

它們是 release/supply-chain evidence，不是 ASCS ontology。

# 14. Migration Tooling

Migration tool MUST 具備：

1. source/target version pin；
2. inventory / preflight；
3. dry-run；
4. backup/checkpoint；
5. explicit step list；
6. restart-safe / non-restart-safe classification；
7. per-step validation gate；
8. identity effect declaration；
9. loss report；
10. rollback procedure。

如果 canonicalization 規則真的改變：

$$
C_{old}\neq C_{new},
$$

就必須 explicit new profile/version；不得同名重定義。

}

# 16. Release Contract

Release manifest MUST 包含：

- release ID；
- package SHA-256；
- schema/profile matrix；
- verification gates + evidence；
- migration range / plan；
- rollback target / procedure；
- known issues；
- implementation release 的 SBOM status；
- optional supply-chain attestation reference。

Release label 不得只由 UI version string 定義。

---

# 17. Rollback Contract

Rollback 必須回答兩個不同問題：

1. 可否回到上一個 application binary？
2. 上一個 binary 是否能保留目前 canonical data？

若 answer 2 是否，則不能叫「安全 rollback」。必須改成：

- read-only preserve；
- explicit reverse migration；
- side-by-side new reader；
- 或 reject rollback。

最重要的不變量：

$$
Rollback\not\Rightarrow RebindImmutableRevision.
$$

# 18. Compatibility Matrix

v0.9 compatibility test matrix 不只驗「能不能 parse」。至少包含：

- schema compatibility；
- canonical hash preservation；
- unknown extension preservation；
- object/revision identity；
- reference resolution；
- candidate/authority；
- resource limit；
- recovery；
- interchange fidelity；
- agent proposal/commit；
- release/migration/rollback。

每個 producer/consumer cell 都必須落在：

$$
\{Exact,Backward,ForwardPreserve,Migratable,Incompatible\}.
$$

- localhost development bridge；
- workspace path confinement；
- per-workspace agent confirmation；
- prompt via stdin；
- agent timeout；
- git snapshot/diff review；
- loopback remote MCP；

- remote bearer token lifecycle；

這些是 migration backlog，不是對現有 prototype 的否定。

# 22. Fail-Closed Rules

以下情況 MUST fail closed 或進 typed degraded state：

- unknown critical policy/profile；
- missing required capability；
- hard resource limit exceeded；
- package hash mismatch；
- corrupt canonical chunk without verified replica；
- migration preflight failure；
- rollback target not verified；
- external effect unknown outcome；
- secret required but no compliant production secret store；
- incompatible producer/consumer matrix cell。

---

# 23. Observability Failure Isolation

目前 Editor 的 monitor 已採 best-effort：log request failure 不打斷 editor。v0.9 將這個行為升格成規格：

$$
TelemetryFailure\not\Rightarrow CanonicalOperationFailure.
$$

只有當某個 operation 本身明確依賴外部服務（例如使用者要求 remote model）時，該 operation 可以因依賴不可用而失敗；telemetry exporter 本身不是 canonical dependency。

---

# 24. Operational Provenance

Release/migration/recovery/benchmark 都需要 provenance，但其 authority 不同：

- object provenance：描述 canonical lineage；
- execution provenance：描述 computation/effect；
- migration provenance：描述 schema/state transform；
- release provenance：描述 package/build/test；
- telemetry：描述 observed runtime signals。

不得只用同一個 `metadata` blob 混在一起。

# 30. 結論

v0.9 把 EveGlyph 從「已定義的 computational document architecture」推到「implementation team 可以安全接手的 operational architecture」。

它真正固定的是：

$$
\boxed{
\text{Bounded}
+
\text{Observable}
+
\text{Explainable}
+
\text{Recoverable}
+
\text{Migratable}
+
\text{Rollbackable}
}
$$

但所有這些能力仍然圍繞同一條根本界線：

$$
\boxed{
\text{Operational Convenience}
\not\Rightarrow
\text{Canonical Authority}
}
$$

因此下一輪可以真正停止設計擴張，進入 v1.0 收斂與本地端交接。
