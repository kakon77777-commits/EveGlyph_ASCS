# v0.8｜Interchange & Legacy Adapter Freeze

**English Title:** EveGlyph ASCS v0.8 — Interchange & Legacy Adapter Freeze  
**作者：** Neo.K / EveMissLab  
**版本：** v0.8  
**日期：** 2026-08-25  
**狀態：** Canonical Handoff Candidate Freeze  
**前置基線：** ASCS v0.1 Architecture + MVP-01；v0.2–v0.7 freezes

---

## Canonical Source Note

本文件以 UTF-8 Markdown 保存正式規格原稿。數學 source 僅使用 `$...$` 與 `$$...$$` 作為 canonical delimiter。

v0.8 不重新定義 EGIR、EGStore、EGCR、NCM、Glyph 或 Agentic Workspace ontology。它只定義：**外部格式、舊文件、靜態投影、binary carrier 與外部識別系統如何進出 EveGlyph，而不取得 canonical authority。**

---

# 1. 問題定義

EveGlyph 若要進入真實生態，不能要求世界先全部改成自己的格式。既有資料大量存在於 Markdown、LaTeX、MathML、OpenMath、SVG、PNG/JPEG、PDF、JSON、CBOR、URI、DOI、DID、SWHID 等系統中。

但如果為了相容舊世界，重新把 Markdown 字串、LaTeX source、SVG DOM、PDF page tree、URL、DOI 或某個 DID 直接當成 EveGlyph object ontology，前面 v0.1–v0.7 所建立的 canonical boundary 就會崩塌。

v0.8 因此只接受以下方向：

$$
\boxed{
\text{Legacy / External World}
\xleftrightarrow{\text{Versioned Adapter}}
\text{EGIR Candidate / Projection / Reference}
}
$$

而不是：

$$
\text{Legacy Format}=\text{Canonical Ontology}.
$$

---

# 2. 核心原則

v0.8 凍結八條最高層原則。

## 2.1 Adapter 不等於 ontology

格式 adapter 是 translation boundary：

$$
A_f:B_f\times P_f\rightarrow(R,F,D,Prov).
$$

其中：

- $B_f$：格式 $f$ 的輸入 bytes / text / document；
- $P_f$：版本化 adapter profile；
- $R$：candidate objects、projection、carrier state 或 external reference；
- $F$：fidelity report；
- $D$：diagnostics；
- $Prov$：provenance。

Adapter 不得因「能解析」就宣稱「已恢復原始作者的 ontology」。

## 2.2 Legacy import 預設 candidate-only

對 legacy document / semantic-math / visual-asset import：

$$
Import_f(x)\rightarrow CandidateSet.
$$

只有後續：

$$
Candidate
\rightarrow Validate
\rightarrow Authorize
\rightarrow Promote
\rightarrow Commit
$$

才可進 canonical state。

## 2.3 Export 只是 projection

$$
Export_f(W)\rightarrow(B_f,F,Prov).
$$

輸出的 Markdown、LaTeX、SVG、PDF 或其他檔案不會反過來重新定義 $W$。

## 2.4 Carrier 與 legacy adapter 分離

合法的 EGIR JSON、CBOR carrier 或已驗證 UTF-8X decoded carrier可以保留既有 local canonical identities；普通 Markdown、LaTeX、SVG、PDF、arbitrary JSON 不可以。

## 2.5 Fidelity 必須多維度報告

「成功匯入」不是單一 boolean。v0.8 必須至少分離：

$$
F=(F_{lex},F_{struct},F_{sem},F_{vis},F_{comp},F_{prov}).
$$

分別代表 lexical、structural、semantic、visual、computational、provenance fidelity。

## 2.6 External reference 不等於 local identity

$$
Resolve_{ext}(r)=Resolved
\not\Rightarrow
A^{id}_{local}=r.
$$

URI / DOI / DID / SWHID 可以是重要 external references，但不能只因 resolve 成功就取得 EveGlyph local persistent identity。

## 2.7 Unknown 不得被 AI 默認猜掉

未知 LaTeX macro、OpenMath content dictionary、SVG metadata、PDF structure 或 extension MUST preserve opaque、produce diagnostic 或 fail-closed；不能在 canonical import pipeline 中靠模型「猜到大概意思」後當成原 semantics。

## 2.8 Version pin 是 conformance 的一部分

所有 adapter MUST pin 它宣稱支援的外部版本與自己的 adapter version。

# 4. Adapter Role

v0.8 定義六種 adapter role：

```text
legacy-document
semantic-math
visual-asset
static-projection
carrier
external-reference
```

它們有不同 authority ceiling。

| Role | Import authority | Typical output |
|---|---|---|
| legacy-document | candidate-only | text/region/object candidates |
| semantic-math | candidate-only | NCM candidates |
| visual-asset | candidate-only | glyph/media candidates |
| static-projection | projection-only | PDF/image/static artifact |
| carrier | preserve-canonical | verified EGIR state |
| external-reference | reference-only | typed reference records |

因此：

$$
\boxed{
LegacyImport\not\Rightarrow PreserveCanonicalIdentity
}
$$

---

# 5. Import Pipeline

標準 import pipeline：

$$
Bytes
\rightarrow DetectProfile
\rightarrow Parse
\rightarrow Map
\rightarrow Fidelity
\rightarrow Candidate
\rightarrow Validate
\rightarrow Review/Policy
\rightarrow Commit.
$$

必要階段：

1. source bytes/hash capture；
2. media/format profile selection；
3. parser version pin；
4. structural mapping；
5. unsupported/unknown feature capture；
6. fidelity report；
7. identity action；
8. candidate authority；
9. deterministic validation；
10. provenance commit。

任何 importer MUST 保存足以回答：

> 這個 canonical object 是由哪一份來源、哪一版 adapter、經什麼損失與決策得到？

---

# 6. Export Pipeline

標準 export pipeline：

$$
CanonicalRevision
\rightarrow ProjectionProfile
\rightarrow Serialize_f
\rightarrow FidelityReport
\rightarrow Artifact.
$$

Export MUST pin source revision：

$$
Artifact\xleftarrow{derivedFrom}A^{ver}.
$$

因此匯出的 PDF 或 LaTeX 即使被修改，也不是原 canonical revision 本身。

---

# 7. Fidelity Model

每個維度使用：

```text
exact
 equivalent
 partial
 none
 unknown
```

## 7.1 Lexical fidelity

source bytes / source text 是否可逐字還原。

## 7.2 Structural fidelity

document tree、math expression structure、vector geometry、group hierarchy 等是否保留。

## 7.3 Semantic fidelity

明確語義是否保留。

## 7.4 Visual fidelity

在指定 renderer/profile/tolerance 下是否保持等價呈現。

## 7.5 Computational fidelity

是否仍可執行原本宣告的 computation / operator behavior。

## 7.6 Provenance fidelity

來源、adapter version、mapping、loss、identity action 是否可追蹤。

---

# 8. Round-trip Classes

v0.8 凍結七種 round-trip classes。

## 8.1 `byte-exact`

$$
Encode(Decode(b))=b.
$$

要求 lexical fidelity 為 `exact`。

## 8.2 `canonical-state`

$$
Decode(Encode(W))\equiv_{EGIR}W.
$$

允許 carrier bytes 不同，但 structural + semantic fidelity 必須 `exact`。

## 8.3 `semantic-equivalent`

$$
Import(Export(W))\equiv_{sem,\Theta}W.
$$

surface syntax 可以不同。

## 8.4 `presentation-equivalent`

要求指定 presentation profile 下：

$$
d_{vis}(V_1,V_2)\leq\epsilon.
$$

但不得因此宣稱 semantic equivalence。

## 8.5 `one-way-import`

可輸入，但沒有承諾反向 export。

## 8.6 `one-way-export`

可輸出 projection，但 re-import 不等於 canonical recovery。

## 8.7 `opaque-reference`

只保存 reference / artifact identity，不解釋內容。

---

# 9. Identity Policy

Legacy import 預設：

```text
allocate-new-local
```

並保存：

```text
importedFrom / derivedFrom / sourceArtifact
```

provenance。

只有真正的 EGIR canonical carrier decode 才可以：

```text
preserve-existing-local
```

外部 ID 若可能與本地 object 對應，只能先產生：

```text
candidate-external-binding
```

直到 explicit authority commit。

---

# 10. Markdown Adapter

v0.8 以 **CommonMark 0.31.2** 作最小 portable Markdown baseline。GFM 等 extension MAY 另作版本化 profile，但不得被默認混入 CommonMark core。

Markdown import 可建立：

- text objects；
- heading/list/table candidates；
- code blocks；
- links / external references；
- declared math-extension candidates。

Markdown 本身不能表達完整 EGIR graph、Canvas placement、NCM proof evidence、glyph topology、agent capabilities。因此 export 通常是 projection/subset。

未知 HTML / directives SHOULD preserve opaque 或 produce diagnostics。

---

# 11. LaTeX Adapter

LaTeX 不是 EveGlyph canonical math source。v0.8 凍結自己的版本化 adapter subset：

```text
eg-latex-subset/1
```

對已識別語法：

$$
LaTeX\rightarrow NCM\ Candidate.
$$

對未知 macro：

$$
UnknownMacro
\rightarrow OpaqueNode+Diagnostic,
$$

而不是：

$$
UnknownMacro\rightarrow AIGuess\rightarrow CanonicalSemantics.
$$

Export 可以依 presentation hints 生 LaTeX，但 LaTeX source 不是 native identity。

---

# 12. MathML Adapter

截至本版 freeze，MathML 4.0 的公開規格狀態為 W3C Working Draft（2026-06-04）；MathML Core 為 Candidate Recommendation Snapshot（2025-06-24）。v0.8 MUST pin 使用的版本。

MathML adapter 必須區分：

- Presentation MathML；
- Content MathML；
- MathML Core browser-rendering subset。

Presentation markup 不能因看起來像某運算就自動取得未明示 semantics。

---

# 13. OpenMath Adapter

OpenMath 官方 normative baseline 仍是 **Version 2.0 Revision 2**。

對已知 content dictionary symbol：

$$
OMS(cd,name)
\rightarrow
SemanticSymbolRef.
$$

對未知 CD / symbol：

$$
UnknownOMS\rightarrow UnresolvedSemanticRef.
$$

不得 drop 或模型猜測後冒充已知 symbol。

OpenMath 是非常適合 NCM semantic adapter 的既有標準，但仍不是 EveGlyph persistent identity system。

---

# 14. SVG Adapter

SVG import 可以高 fidelity 保存：

- path geometry；
- groups；
- transforms；
- paint/style hints；
- text/vector references；
- viewBox / coordinate information。

但：

$$
SVGGeometry\not\Rightarrow SemanticGlyphBinding.
$$

任何 script / event / external executable behavior MUST disabled on import，並交由 v0.6/v0.7 behavior-capability boundary 處理。

SVG DOM ID 也不得直接成為 global EveGlyph persistent identity。

---

# 15. Raster Adapter

PNG/JPEG/WebP 等 raster 預設只有 visual evidence：

$$
RasterImport\rightarrow VisualCandidate.
$$

若再經 GSC：

$$
Raster
\rightarrow GSC
\rightarrow StructuralGlyphCandidate.
$$

GSC 成功不等於 semantic symbol binding 成功。

因此 v0.6 的：

$$
ExactReconstruction\not\Rightarrow SemanticUnderstanding
$$

在 v0.8 繼續保持。

---

# 16. PDF Boundary

v0.8 將 PDF 主要定位為 **static projection / document interchange artifact**。Baseline pin 為 ISO 32000-2:2020（PDF 2.0）。

$$
Export_{PDF}(W)=ProjectionArtifact.
$$

PDF 可能包含 text、tags、structure、annotations、embedded files 或 metadata；adapter MAY 利用這些資訊提升 import fidelity，但不得宣稱任意 PDF re-import 可以恢復原 EGIR world。

因此：

$$
Import_{PDF}(Export_{PDF}(W))\neq W
$$

是合法且預期的情況。

---

# 17. JSON Boundary

只有符合 EGIR profile/version/schema/hash contract 的 JSON 才能被視為 canonical EGIR carrier。

任意：

```json
{"foo":"bar"}
```

不能因為「是 JSON」就被讀成 EGIR。

Arbitrary JSON 可以進 `data` object / candidate importer，但沒有 canonical-preservation privilege。

---

# 18. CBOR Boundary

RFC 8949 CBOR 可以作 binary carrier。v0.8 不把「CBOR bytes hash」與「EGIR semantic identity」混在一起。

對 deterministic carrier profile：

$$
Decode_{CBOR}(Encode_{CBOR}(W))\equiv_{EGIR}W.
$$

若兩個 CBOR serializers 產生不同 bytes 但解碼後 canonical EGIR 相同，兩份 carrier artifact 可以有不同 physical hash，而上層 object identity 仍相同。

---

# 19. UTF-8X Boundary

歷史 UTF-8X 仍是 optional physical representation / legacy carrier adapter。

必要條件：

$$
Decode_{UTF8X}(X)=B_{EGIR}
$$

並通過 TW-01/TW-02 hash/schema validation。

AI 可以在 encode policy 參與選擇，不能進 deterministic decode function。

---

# 20. External Reference Model

v0.8 external reference record：

$$
R_{ext}=(scheme,value,resolution,binding,provenance).
$$

`resolution` 與 `binding` 必須分離。

$$
Resolve(r)\rightarrow location/metadata
$$

不等於：

$$
BindLocalIdentity(r,o).
$$

---

# 21. URI Adapter

RFC 3986 URI 作 generic resource identification syntax reference。

URI 可以同時被很多 resolution/application scheme 使用；URL-like locator 變動也不應自動改 EveGlyph persistent identity。

URI record 預設：

```text
binding.mode = reference-only
```

---

# 22. DOI Adapter

DOI name 是 persistent identifier，resolution 通常透過 DOI/Handle infrastructure 得到目前服務／位置／metadata。

v0.8 保存：

```text
DOI name
resolver profile
resolution state
observed locations
observed timestamp
```

但：

$$
DOIResolved\not\Rightarrow LocalIdentityBound.
$$

DOI 對應的 referent 與 EveGlyph object 的 identity-equivalence 仍需要 explicit binding decision。

---

# 23. DID Adapter

截至 v0.8，DID v1.1 的公開狀態為 W3C Candidate Recommendation Snapshot（2026-03-05）。

DID 可以提供 decentralized identifier / DID document / method-specific resolution evidence，但 v0.8 不假設：

$$
DID=EveGlyphPersistentID.
$$

更不能：

$$
Resolve(DID)\Rightarrow CapabilityGranted.
$$

任何 capability 仍由 v0.7 runtime policy 發放。

---

# 24. SWHID Adapter

SWHID v1.2 已成為 ISO/IEC 18670:2025，可作 software artifacts 的 intrinsic content-derived reference。

它非常適合：

- source-code provenance；
- archived software references；
- reproducibility evidence；
- external content identity evidence。

但：

$$
SWHID\neq EveGlyphPersistentObjectID.
$$

SWHID 可作 content evidence / external reference；是否與某 local object lineage 綁定仍需 explicit authority。

---

# 25. Federated Binding

v0.8 允許未來 federation，但要求最嚴格模式：

```text
binding.mode = federated-binding
binding.authority = explicit
capability = identity.bind.external
binding_event = <provenance event>
```

所以 resolver、adapter、AI 都不能自己完成 federated identity merge。

---

# 26. Loss Diagnostics

任何 non-exact mapping MUST 能報：

- loss code；
- severity；
- source/path；
- human-readable description；
- unsupported features；
- round-trip impact。

例如：

```text
LATEX-UNKNOWN-MACRO
MATHML-PRESENTATION-AMBIGUOUS
SVG-SCRIPT-DISABLED
RASTER-VISUAL-ONLY
PDF-STATIC-PROJECTION
MARKDOWN-EXTENSION-OPAQUE
```

「匯入成功但有損」必須與「無損成功」可區分。

---

# 27. Opaque Preservation

若 parser 能界定一段資料但不能理解 semantics，SHOULD preserve：

$$
Opaque=(format,version,sourceHash,payload,location).
$$

Opaque node 可以未來由更高版本 adapter 重新解析。

這優於：

1. 丟掉未知內容；
2. AI 猜測後永久 commit；
3. 直接阻止所有 import。

---

# 28. Security Boundary

Importers MUST 預設資料而非程式。

特別是：

- SVG scripts/events 不執行；
- PDF embedded actions 不執行；
- Markdown raw HTML 不取得 runtime authority；
- LaTeX shell escape 不執行；
- external links 不自動 network-fetch，除非有 capability；
- DID/DOI resolver 不自動授予 identity/capability；
- opaque payload 不自動 evaluate。

因此：

$$
ParseSuccess\not\Rightarrow ExecutePermission.
$$

---

# 29. Import + v0.7 Agent Boundary

AI-assisted importer 可以協助：

- classify unknown structure；
- propose semantic mappings；
- propose identity matches；
- generate diagnostics；
- suggest fallback adapters。

但結果仍是：

$$
AIImportProposal\rightarrow Candidate.
$$

不能跳過 v0.7：

$$
Validate+Capability+Review+Commit.
$$

---

# 30. Cross-format Projection

同一 canonical object 可以同時有：

$$
\Pi_{Markdown}(o),
\Pi_{LaTeX}(o),
\Pi_{MathML}(o),
\Pi_{SVG}(o),
\Pi_{PDF}(o).
$$

這些 projection 可以在 lexical/visual 結果上完全不同，卻仍指向同一 source revision。

因此：

$$
ProjectionEquality\not\Rightarrow ObjectIdentityEquality.
$$

---

# 31. Adapter Registry

本地端實作 SHOULD 有 registry：

```text
adapter_id
role
directions
format/version pins
authority mode
round-trip class
unknown-feature policy
implementation version
test-vector set
```

同一格式可以有多個 adapter profile，但必須明確選擇，不能依 runtime 隱式改變。

# 34. v0.8 Design Freeze

完成 v0.8 後，v0.9/v1.0 不得在未顯式升版的情況下破壞：

1. Legacy format adapter 不等於 ontology；
2. Legacy import 預設 candidate-only；
3. Export artifact 是 projection；
4. Carrier 與 legacy adapter authority 分離；
5. Fidelity 是多維向量；
6. Round-trip class 必須顯式宣告；
7. `byte-exact` 要求 lexical exact；
8. `canonical-state` 要求 structural + semantic exact；
9. semantic-equivalent 不要求同 lexical bytes；
10. presentation-equivalent 不推出 semantic equivalence；
11. legacy import 預設 allocate new local identity；
12. 只有 verified canonical carrier 可以 preserve existing local IDs；
13. external reference resolution 與 local identity binding 分離；
14. federated binding 需要 explicit authority；
15. federated binding 需要 `identity.bind.external` capability；
16. source hash 與 adapter version 進 provenance；
17. unknown semantic feature 不允許 silent AI guessing；
18. unknown structures SHOULD opaque-preserve or diagnose；
19. Markdown baseline pin CommonMark 0.31.2；
20. LaTeX 使用 EveGlyph-defined versioned subset/profile；
21. MathML presentation/content 分離；
22. OpenMath CD mapping 必須版本化；
23. SVG geometry 不推出 semantic glyph binding；
24. SVG executable behavior import-disabled；
25. Raster 預設 visual-only；
26. GSC structural lift 不推出 semantics；
27. PDF 主要是 static projection boundary；
28. arbitrary JSON 不得冒充 EGIR；
29. CBOR carrier bytes identity 與 EGIR identity 分離；
30. UTF-8X decode 不依賴 AI；
31. DOI / DID resolver 不授予 capability；
32. SWHID 可作 intrinsic external content evidence但不是 local lineage identity；
33. adapter registry profile selection必須顯式；
34. import security 預設 data-not-code；
35. AI-assisted mapping 仍進 v0.7 candidate pipeline；
36. v0.8 不修改既有 canonical hash preimages。

---

# 35. Compatibility Freeze

v0.8 是 additive adapter/interchange layer。

因此：

$$
\boxed{
v0.7\rightarrow v0.8
\text{ requires no mandatory canonical migration}
}
$$

既有 EGIR objects、NCM、Glyph、history、Canvas、agent records 完全可以原樣存在。

只有當使用者新 import/export/resolve external resources 時，才產生新的 adapter/result/fidelity/reference records。

---

# 36. 與 v0.9 的接口

v0.9 不再擴格式 ontology。它接手：

- security/resource budgets；
- operational failure matrix；
- observability / explainability；
- benchmark/performance budgets；
- packaging layout；
- migration tooling；
- release/rollback；
- compatibility matrix。

v0.8 只要求 v0.9 能觀察與診斷 adapter pipeline，不重新定義 adapter semantics。

---

# 37. 非主張

v0.8 不主張：

- EveGlyph 可無損理解任意 PDF；
- LaTeX 可以完美轉 NCM；
- SVG geometry 具有內建 semantics；
- OCR/raster recognition 等於原結構恢復；
- DOI/DID/SWHID 與 EveGlyph identity 是同一件事；
- CBOR/UTF-8X 是唯一 binary carrier；
- 所有 Markdown dialect 可以用同一 parser 無損處理。

本輪只主張：

> **每一次跨格式邊界，都必須明確知道自己保留了什麼、失去了什麼、誰有權把結果變成 canonical state。**

# 38. 結論

前面七輪回答的是：

$$
\text{What is the world?}
$$

v0.8 回答的是：

$$
\boxed{
\text{How can other worlds enter and leave without becoming the world model?}
}
$$

因此整個 v0.8 可以壓成：

$$
\boxed{
\text{Adapter}
+
\text{Fidelity}
+
\text{Round-trip Class}
+
\text{External Reference}
+
\text{Authority Boundary}
}
$$

完成後，EveGlyph 已經不需要在「相容舊生態」與「保持 native canonical architecture」之間二選一。
